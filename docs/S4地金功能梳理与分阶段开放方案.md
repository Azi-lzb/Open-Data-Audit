# S4 地金工具：功能梳理与分阶段开放方案

日期：2026-10-13。状态：源码盘点初稿，待业务人员确认。

本轮只整理功能、复用边界和交付方案，没有新增导航、前后端、系统注册或配置迁移。
依据是 `地金工具/VBA_Export/` 的导出源码以及当前 `core/`，另只读检查了原工作簿的工作表元数据。
未执行 VBA、读取业务数据行、验证导出源码与嵌入 VBA 完全一致，或开展真实数据对拍。

## 一、目前能识别哪些功能

### 1. 当前代码创建的菜单：5 个一级菜单、6 个可点击业务入口

菜单来源：`VBA_Export/Documents/ThisWorkbook.cls` 的 27–59 行。以下是入口存在的证据，不能代替业务验收或“目前仍在使用”的确认。

| 业务入口 | 输入与用途 | 输出/修改对象 | 主要源码证据 |
|---|---|---|---|
| 两期比较：Excel 长表 | 本期、上期地金长表；再校验报告；可选基础数据校验文件。比较两期数据，并结合参照、规则与说明生成提示。 | 新的跨期比较结果工作簿。 | `广东地金系统跨期比较.bas`：`ShowDoDjKqCompare`、`广东地金系统跨期比较过程`（632–745）；`跨期比较窗体.frm`（21–100）。 |
| 与基础数据比较 | 地金长表与基础数据导出，通过机构、指标参照对齐两来源数据。 | 跨系统差异结果，源码构造 12 列结果；有只保留提示数据的选项。 | `地金基础数据跨系统比较.bas`：`基础数据比较`（32–116），数据合并与结果构造（263–424）。 |
| 与大集中比较 | 地金长表与大集中导出；使用机构、指标及“大集中比对参照”中的两侧取数口径。 | 跨系统差异结果，源码构造 9 列结果；有公式聚合、单位处理和差异提示。 | `与大集中比较.bas`：`大集中数据比较`（37–104），参照装载（107–197），两侧取数及结果（307–488）。 |
| 报文错误信息库更改 | 校验报告与待处理的报文工作簿；窗体有再校验/跨期报告处理分支。 | 更新报文中的错误信息区域。旧 VBA 先留备份，再保存原文件。 | `ShowDoCWXXGK`、`错误信息库更改窗体.frm`（37–93）；主模块的两个“重写汇总报文错误信息库”过程（161–401）。 |
| 两期比较：单机构报表模板 | 单机构本期/上期报表，根据指标参照定位表格单元格。 | 新的单机构比较结果工作簿。 | `广东地金系统跨期比较过程_单机构`（464–567）；对应模板数据初始化（1313–1550）。 |
| 再校验报告：查收说明 | 一份待汇总的总再校验报告，以及多份反馈文件。 | 将反馈回填到所选报告的工作表；该过程没有显式保存语句，最终保存方式需确认。 | `说明模块.bas`：`zjy_load_sm`（497–593），回填位置（560–586）。 |

建议未来 S4 先保留这 6 个入口的业务边界。长表和单机构模板可以共用底层比较，但是否合成一个功能的两种模式，留待业务确认。
这里只做候选清单，不登记正式 `S4-Fxx`，不提前更改版本清单。

## 二、配置和数据依赖

原工作簿有 20 个工作表，包含隐藏配置和测试/辅助表。隐藏状态不代表可删除，名称含“测试”也不能直接作为排除依据。

| 来源 | 已看到的作用 |
|---|---|
| 执行面板 | `通用.bas:60–74` 的 `InitMBcz` 将 A/B 列参数装入全局参数字典。 |
| 基本配置 | `CMyConfigTool.cls:12,78–108` 的 `GetConfig` 按键名查找，支持数组参数。 |
| 指标参照、机构参照 | 单机构定位、跨系统机构/指标映射、导出数据属性。 |
| 特殊指标-自定义 | 特殊业务检查的动作、条件及说明。 |
| 复杂校验-自定义 | 表达式规则与适用范围。 |
| 大集中比对参照 | 地金与大集中两侧指标口径及聚合表达式。 |
| 警戒区间 | 区间、颜色、提示等校验设置。 |
| 加权平均参照 | 特定参数开启时参与处理。 |
| 更新日志 | 主模块及二次校验模块还从该表单元格读取复杂规则容差，不能将它当成纯说明页直接丢弃。 |

本轮没有读取这些表的业务数据或规则行，也没有统计正式启用规则数量。
实际迁移时需逐项建立“旧表/字段/参数 → 新配置/读取器/检查器/执行链”的映射，解释排除项和数量变化。

## 三、哪些能与 S3 复用

有明显的共源机制；可复用程度需要按数据口径和对拍结果确定，暂不估算复用百分比。

| 层次 | 候选复用能力 | 必须保留的 S4 差异 |
|---|---|---|
| 公共基础设施 | 文件选择适配、日志、取消任务、输出路径、Excel 静态读写、平台计算适配。 | 保留地金的输入格式和报文结构，不能沿用写死的原列号而不建立映射。 |
| 标准记录与索引 | S3 的记录/数据集/机构指标索引构建机制。参考 `models.py` 的 `CentralRecord`、`CentralDataset`。 | S4 的机构代码、地区、指标、属性、频度、批次是否能映射到该模型需逐项核对。 |
| 两期计算 | S3 `comparison_engine.py` 的两期对齐、单边记录及单位处理思路。 | 长表、单机构模板、二次校验的输入和初始化不同；先做各自适配再调用公共计算。 |
| 规则执行 | S3 `indicator_rule_engine.py`、`rule_action_engine.py`、`complex_rule_engine.py` 的规则准备、适用性检查和求值机制。 | 地金原自定义表不是 S3 现配置的同一协议，需映射规则动作、token、启停、阈值和说明落点。 |
| 跨系统比较 | 可共用取数、单位换算、表达式计算和结果写出工具。 | “与基础数据”“与大集中”有不同机构映射和两侧口径聚合，不能直接当成 S3 两期比较。 |
| 说明反馈 | 可共用批量文件读取、说明合并、未匹配/冲突报告和导出工具。 | 地金当前主要按机构代码后 18 位与指标代码匹配；S3 当前用机构、指标、金额、差额四字段，匹配策略要分别保留。 |
| 台账拆分 | 可复用通用 Excel 分组、拆文件能力。 | 它按用户选列拆台账，和 S3 按金融模板生成报表是不同业务。 |

未来落点仍是 `core/`：共用能力由 S3/S4 调用，地金特有输入、映射和流程放在 S4 的业务目录。
两个外壳保持共用核心。原始 VBA/XLSM 作为迁移来源留存，不复制成另一套生产实现。

## 四、建议带给业务人员确认的问题

| 优先级 | 要问什么 | 为什么要问 |
|---|---|---|
| 必须 | 正式系统名称是什么？六个菜单入口分别哪些仍在使用？ | 决定导航名称、正式范围和优先级。 |
| 必须 | 每个功能能否提供一组脱敏输入、配置及旧工具输出？ | 建立真实格式与业务验收基线。 |
| 必须 | 长表/单机构模板的导出路径、文件类型、工作表名、日期来源是什么？ | 不能仅根据代码中的列位置猜输入协议；还需确认是否支持旧 `.xls`。 |
| 必须 | 长表比较是否必须选再校验报告？ | 窗体将它设为必填，初始化代码有可跳过分支，口径不完全一致。 |
| 必须 | 两种跨系统比较的金额单位、判等方式、指标例外、聚合运算是什么？ | 现地金与 S3 的判等/映射不是完全一致，不应直接替换。 |
| 必须 | 报文错误信息库要交给哪个系统导入？能否用新副本交付？ | 旧代码保存原文件；本项目要求保护原始业务文件，需要先确定迁移输出方式。 |
| 必须 | 多份反馈对同机构同指标有不同说明时，追加、保留还是提示冲突？回填后谁保存？ | 旧字典赋值和说明合并存在覆盖/保留分支，不能直接套 S3 四字段策略。 |
| 必须 | 自定义规则的正式启用数量、废弃原因和维护人员是谁？ | 建立数量账及配置执行性验收。 |
| 后续 | 二次校验、长期数据、说明转接、台账拆分是否仍需迁移？ | 源码存在不等于当前常用，也不能未经确认删能力。 |
| 后续 | “更新日志”中的容差和“执行面板/基本配置”的参数是否仍有效？ | 将隐藏的业务参数显式迁出，避免漏迁。 |

另外应核实跨期比较中多种校验提示写到同一键时，后写覆盖前写是否符合业务预期。
业务人员反馈后再定正式功能编号、配置拆分及迁移顺序。

## 五、交付采用同一程序，按阶段开放系统

用户最新选择：通过彩蛋入口及口令控制开放范围，不制作 S1/S2/S3 的独立代码或独立程序包。

| 阶段 | 普通用户看见的业务导航 | 对应交付材料 |
|---|---|---|
| 首批 | S1 逐笔统计、S2 报表采集、设置中心 | S1 与 S2 各自的功能清单、配置说明、培训材料及验收记录。 |
| 后续开放 S3 | 在首批基础上增加大集中统计 | S3 的配置、业务操作指引、样本对拍和独立验收记录。 |
| S4 完成并验收后 | 增加地金系统 | 已确认的 S4 范围、旧配置映射、输入输出对拍及验收记录。 |

按系统记录开发、配置整理、测试、培训、验收等实际成果，可以清楚体现每一阶段的工作量。
系统开放记录与业务组件版本分别管理；仅开放已经实现的功能，不把 S4 规划当成已交付。

### 1. 彩蛋入口建议

- 候选：在“关于”页产品名称上连击 7 次，打开解锁窗口，输入管理员口令，再选择开放的系统。
- 当前设置中心连击 5 次用于高级设置，逐笔导航连击 5 次用于低频功能；新入口使用独立位置，避免混在一起。
- 默认开放 S1、S2，S3 不显示；S4 在实现前不加入可开放的系统列表。
- 开放结果保存在共用的本机设置中，重启保留，两种外壳一致；浏览器本地缓存只辅助显示。
- 升级保留已开放范围；支持重新隐藏。任务执行期间先不切换范围，隐藏当前页时回到已开放系统。
- 口令用于管理分阶段开放，具体口令及是否区分 S3/S4 开放口令，等实施时确认。

以上是方案，本轮没有修改彩蛋或新增口令。

### 2. 一套系统开关，同步控制所有入口和内容

| 位置 | 首批 S1/S2 范围应怎样显示 |
|---|---|
| 主导航、业务页面 | 只出现已开放系统；启动页为首个开放系统；快捷入口也遵守同一范围。 |
| 常规设置 | 只显示 S1/S2 配置绑定及其通用设置，S3 的四册配置入口不出现。 |
| 高级设置、组合配置、模块/DAG 目录 | 按系统与具体功能筛选；原高级彩蛋和逐笔低频彩蛋仍是独立开关，不能顺带开放 S3。 |
| 操作指引 | 每项标记所属系统/功能，只渲染已开放内容；展示编号自动连续。 |
| 常见问题 Q/A | 每条按系统/功能归属筛选，分类标签和搜索结果只统计可见条目。 |
| “源数据总核对”等混合问题 | 拆成可按系统显示的段落，避免归到“通用”后仍暴露全部系统流程。 |
| 更新日志 | 单条记录标记系统归属；仅展示已开放系统和公共界面条目，保持同日归并。开发日志保留全量。 |
| 环境/诊断导出 | 公共环境保留；配置清单、快照和检查只含已开放系统，计算依赖按实际需要说明。 |
| 关于页 | 显示统一产品版本与当前开放范围，便于支持人员辨认阶段。 |

特别注意：S2 的“大集中数据文件”是外部核对的数据来源，S3 导航隐藏后，S2 仍需保留该输入及其说明。
UOS 下 S1 也会用 LibreOffice，不能因隐藏 S3 就一并隐藏 S1 所需的计算环境说明。

### 3. 未来实现要覆盖的核心边界

当前代码的三个业务导航、操作指引列表、Q/A 分类和各册配置初始化均固定包含现有系统；尚没有交付范围控制。
两个已有彩蛋只处理局部高级/低频入口。新方案需统一处理：

1. 核心提供已实现系统与已开放系统清单，实际可用范围为二者交集。
2. 共享 WebApi 向两个外壳返回同一范围，业务调用和页面导航都检查范围。
3. 初始化、配置检查、重置与诊断导出只处理当前开放系统；开放 S3 时再装载其配置和检查状态。
4. 设置、指引、Q/A、更新日志按系统/功能归属筛选，复用同一判断，不各写一套列表。
5. 系统范围开关与已有高级/低频功能开关组合判断，保持互不误触。

后续验证应覆盖默认 S1/S2、开放 S3、重新隐藏、重启/升级、两种外壳，以及 S2 外部核对仍正常可用。
本轮仅记录这些验收点，没有实现或运行测试。

## 六、建议实施顺序

1. 本轮：完成源码功能盘点、交付方案和业务询问清单。
2. 业务确认：先确认六个菜单入口的样本、使用状态、配置和输出口径。
3. 若决定先交付 S1/S2：先实施现有系统的统一开放开关及内容筛选，S4 继续保持规划状态。
4. S4 迁移：优先迁移最常用、已有样本的流程；建立配置数量账，并逐项评估 S3 的公共能力复用。
5. 各系统按真实范围分别培训、验收和记录开放日期。

没有 S4 实现时不升级为新增平台的大版本；真正实现并发布 S4 时再按产品版本规则评估大版本升级。
