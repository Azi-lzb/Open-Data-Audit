## 1. 结论与证据边界

以纯 Python 实现 S4 是可推进的目标。导入、名单管理、筛选、聚合、比较、报告和反馈匹配可以迁为独立业务流程；真正困难的是原 Excel/VBA 的类型、舍入、缺值、公式引用、自定义函数和输出宏语义。尚未完成规则编译、运行或黄金对拍，因此当前不能宣称两套工具已等价复刻。

生产链不使用 Excel/WPS COM、VBA、ActiveX、LibreOffice/UNO 或后台 Office 重算。openpyxl/OOXML 只承担静态文件读写；Python 负责实际计算。旧公式缓存不得成为本次审核结果，未知函数不得按“未触发”继续运行。

S4 不直接或间接依赖、复制 S3 业务模型、引擎和公式后端。保留 S1/S2/S3 当前行为，通过独立 S4 数据模型、配置、编译器、任务状态和结果模型隔离变更。

来源为现有导出的 VBA、工作簿只读结构/配置和操作笔记；未运行宏、保存源文件、重新提取 VBA或验证导出源码与嵌入 VBA 完全一致。旧省行 v1.2.9.4 分析仅作历史线索，当前来源以 v1.2.9.6 文件为准。

## 3. 两个工具在实际季中流程中的分工

操作笔记给出的主流程是：

```text
外部平台人工审核并导出本期/上期
  → 总行：机构/日期/频度核对，建立两期数据，汇总、错误报告与再校验
  → 省行：两期比较、与基础数据/大集中数据核对
  → 说明反馈与涉及改数的重跑
  → 生成交付文件，人工完成外部平台审核/提交
```

总行“报文”是 Excel 工作簿协议，不能按名字推断为文本报文。内部平台登录、退回、审核、完备率计算和强制提交均属外部人工流程，不纳入 S4 自动操作。

需要贯穿保存的五类交付物为：批量汇总数据表、汇总季报、再校验报告、跨期校验结果、两套数据一致性审核结果。源工具版本号、报表制度版本、S4 产品版本是不同身份，不能互相替代。

笔记中反复清空、改日期、重新导入可以在 S4 中表达为独立的本期/上期快照与显式任务计划；前后期数据、名单及频度仍须分别核对。未知机构不能自动加入合法名单。完备率不能无依据填写 100%。

## 4. 实际规模与统计口径

| 来源 | 工作簿结构 | VBA 导出文件 | 真实公式单元格 |
|---|---|---|---:|
| 总行 | 59 张表 | 5 个标准模块、61 个文档类模块 | 25,794 |
| 省行 | 19 张表 | 10 个标准模块、27 个类/文档模块、2 个窗体及 2 个资源文件 | 9,082 |

来源目录共 110 个文件：总行 67 个、省行 42 个、操作笔记 1 个。主 Agent 已对这些文件及 328 个现有跟踪文件、19 个本机真实配置文件建立 SHA-256 基线。

总行公式中有 16,890 个共享公式节点；省行有 235 个。需要展开相对引用，不能只审计基公式文本。公式字符串中的报错文案不能误识别为函数。总行静态公式确认调用两个 VBA 自定义函数：社会信用代码校验和前本期客户名称变化。

总行再校验表 21,246 个公式中，H/I 基础计算列占 8,106 个，K:X 校验公式槽占 13,140 个。这是源公式槽位数量，仍不等于独立规则族或未来正式规则数量。配置字符串、展示公式、聚合公式、自定义函数调用、业务规则实例必须分账。

省行实际公式数按单元格类型和 OOXML 双重核对。基本配置中另有 16 个以 `=` 开头的非公式字符串，不能算成 Excel 公式，也不能因是文本就忽略其表达式/宏模板来源作用。规则启停计数与是否真的可执行须分别核对，旧运行日记只能作为历史佐证。

省行按本版读取条件得到的候选启用行：复杂校验 225/369、特殊指标 1,071/3,856、指标参照 3,964/4,055、大集中比对参照 1/12。不同能力使用不同读取分支，一行还可能拆出多个目标；这些计数不是已执行或已覆盖的规则数，不能用于直接宣布迁移完成。

基本配置另有三个用于注入输出文件的宏模板，分别包含菜单/事件 5 个过程、工作模块 11 个过程和通用模块 27 个过程。它们承接离线说明处理，必须纳入迁移台账。复杂规则初始化中存在失败计数后排除规则、仍继续执行的旧行为；新 S4 按项目硬约束改为逐项报告并阻断相关功能，明确记录与旧工具的失败处理差异。

## 5. 界面如何简化

建议保留左侧 S4 导航，S4 内按业务任务组织，而不是复制 59 张总行工作表及每个按钮。

```text
地金系统
  数据与机构 | 汇总与报送 | 审核与比较 | 说明与反馈 | 结果与记录

任务：季中审核 / 单项操作
本期：文件、日期、频度     上期：文件、日期、频度
名单与配置：已检查 / 待确认
当前步骤：所需输入 → 检查问题 → 执行 → 查看结果及来源
```

| 原操作 | 候选新交互 | 业务保留要求 |
|---|---|---|
| 重复清空主库、修改日期并重导两期 | 本期/上期分角色导入，独立快照 | 同名、重复、补报、替换及跨期启停策略必须显式确认。 |
| 红色机构加入合法名单后再导入 | 待确认机构列表与名单变更记录 | 不自动合法化机构，不自动覆盖机构身份。 |
| 主库/报表下拉、上一张/下一张、跳转主库 | 结果表筛选、机构/报表详情、来源定位 | 保留报表身份、指标顺序、来源坐标和筛选范围。 |
| 推送选中表/全部表、批量汇总操作 | 选择范围后一次执行对应汇总计划 | 不能把不同聚合方式、地区/类别组合混为同一计算。 |
| 分机构行/列校验、跨期启停、再校验 | “审核与比较”中的明确模式和机构范围 | 行、列、再校验与跨期语义分别登记。 |
| 手工复制报表工作表另存 | 自动输出约定的报表副本与交付清单 | 表头、类型、说明、格式、命名及接收方兼容性需对拍。 |
| 宏菜单查收反馈、错误库改写 | 文件选择、匹配预览、冲突确认、新副本输出 | 保留反馈键、覆盖顺序及输出宏承担的业务。 |

配置维护放入 S4 自己的次级面板，不改动其他系统的设置和指引。总行/省行来源作为任务标识保留，不能为了少几个按钮合并不同业务口径。当前 S4 默认禁用与“开放”标题五连击开发入口继续保留。

## 6. 伪数据如何支撑迁移

伪数据生成器是后续实施交付物，本轮先确定契约。每个案例先指定规则、作用域、取数依赖与独立期望，再生成文件，不通过随机数猜测触发。

- 每条可执行规则覆盖触发、不触发、必要边界、合法跳过及相关负面场景。
- 数值边界按规则单位与有效精度构造；同时测试舍入前/后、负数、空值与存在零。
- 文本/机构/频度/日期/名单/重复键/反馈冲突等非数值规则也建立场景义务。
- 先单规则最小案例，再组合案例，最后跑完整季中交付流程。互斥规则用不同案例，不要求一个文件全部触发。
- 使用固定种子、稳定排序、案例版本和配置指纹，记录生成参数、输入清单、预期结果、差异及失败原因。
- 期望值来自人工规格/手算或原工具离线黄金输出，不能用被测 Python 求值器自行生成答案。

源规则 → 支持状态 → 用例 → 实际执行/跳过/触发 → 黄金差异，必须通过规则 ID 串联。行号是来源坐标，不应单独承担跨版本稳定身份。对缺少触发案例的规则，明确登记无法满足、规则疑点、缺输入或人工待确认等原因，不缩小分母后报告 100%。

生产链不依赖 Office；原 VBA 离线结果仅用于独立参考验收。使用真实配置构造的伪数据仍可能泄露真实规则和映射，生成工作簿、黄金及差异证据放在被忽略的本机验收目录；公开仓库只保留安全的生成逻辑、空结构和匿名最小算子样例。

## 8. 需要业务确认的集中问题

1. 总行/省行哪些潜在或维护入口属于正式交付范围，哪些明确延期？
2. 导出的 VBA 是否对应当前两个工作簿？总行多出的文档类模块及省行版本标记差异如何处置？
3. 实际输入报文、外部填报校验程序与输出报告样例有哪些？公式导入提示的制度版本要求如何确认？
4. 原 VBA 的疑似优先级/缺值降零/未知单位/反馈覆盖等行为，是保留兼容还是确认修正？启用规则解析失败或非法配置须阻断是既定约束，不将保留静默漏跑作为选项。
5. 输出文件中的哪些宏动作必须迁成 S4 内置命令，接收方是否接受无宏反馈模板及回传协议？若现有外部往返协议硬性依赖执行宏，登记其与纯 Python 目标的冲突，不把执行旧宏作为 S4 运行回退。
6. 名单新增、同机构补报/改报、重复文件、反馈冲突和改数后重跑的确认规则是什么？
7. 汇总季报版本标识、完备率和文件命名由哪些正式口径决定？
8. 第一阶段优先交付总行数据汇总、省行比较还是完整常用季中链？可提供哪些人工/原 VBA 黄金结果？

业务未知项不由界面简化决定。可确认的基础结构和静态流程可以独立推进；涉及结论变化的口径必须先有证据和业务决定。
