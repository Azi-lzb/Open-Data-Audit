# 悬空外部引用缺陷：机制说明与跨仓库结论

日期：2026-11-07
适用：3.open-data-audit（本仓库，旧 audit 实现）与 Rust-Audit（新实现）共用规则。

## 一、缺陷机制

模板作者用“外部工作簿链接”写条件格式/校验公式，公式文本形如：

```
INDEX([1]集中系统数据!$1:$1048576, MATCH(VLOOKUP($B$4,[1]参照表!$A:$B,2,0), ...))
```

`[1]` 对应 workbook.xml 第 1 个 `<externalReference>`，模板自带
`xl/externalLinks/externalLink1.xml`（目标通常是作者机器的绝对路径，早已断链）。
模板自身能打开，因为 Excel 用**缓存值**兜底渲染，不立即解析外链。

审核副本管线做了两件事：

1. 把外部工作簿导入为**本地工作表**（本仓库 `DirectOoxmlExternalSheetWriter`，
   导入后 `集中系统数据`、`参照表` 成为本地 sheet）；
2. 复制模板校验区域公式原文（本仓库 `DirectOoxmlFormulaRegionWriter`，
   **零处处理 `[N]` 前缀**，原样写入）。

而副本按 ZIP 级重写，**不含 `xl/externalLinks/*`**（本仓库确实不复制外链部件，
导入路径只写 sheet/rels/Content_Types）。于是公式里的 `[1]` 指向一个副本中
不存在的外部簿 → **悬空引用**：

- **Excel COM**：`Workbooks.Open` 直接拒绝，HRESULT `0x80020009`
  （"类 Workbooks 的 Open 方法无效"）；
- **WPS**：宽松忽略断链可打开，但重算丢失公式或回落到断链缓存值；
- **LibreOffice**：同样受影响。

## 二、本仓库实证（2026-11-07）

因果实验（`test-output/s1f1_mode_parity_20261107/causal_tmp/clean/`）：

| 步骤 | 文件 | Excel COM 只读打开 |
|---|---|---|
| A | 真实核查表复制 + 导入外部表为本地 sheet（无 `[N]` 公式） | **OK，7 张表** |
| B | 同上 + openpyxl 合法写入 `=INDEX([1]集中系统数据!$1:$1048576,1)` | **FAIL 0x80020009** |
| C | B 经 `repair_audit_copy_for_excel` 剥离后 | **OK，7 张表** |

唯一变量是那条悬空 `[1]` 公式——机制坐实。

**重要方法学教训**：首次实验用“在 sheetData 末尾追加 `<row r="152">`”注入公式，
那次 FAIL 混入了结构非法因素（去掉该行即恢复可开）。重做时改用 openpyxl 写入
（保证结构合法）才得到干净结论。任何后续实验都应以“结构合法 + 单一变量”为准。

验收四条（全部通过）：

1. 修复副本 Excel COM 只读打开成功，表数正确（7/7）；
2. WPS 打开并重算，B2 公式仍为 `=INDEX(集中系统数据!$1:$1048576,1)`，未丢失；
3. 原始报送文件 SHA-256 前后一致；
4. 公式语义指向**本地已导入**的同名表（`集中系统数据!`，无 `[1]`）。

## 三、真实数据分布

- 本仓库 `test-data/S1F1_external_fallback_20261106`：**0/129 报送、0/19 模板**
  含外链部件或 `[N]` 引用。因此该数据集上 129/129 全通是**数据干净**而非管线免疫。
- Rust-Audit `business_templates/！70.金融基础数据采集（债券业务）202608.xlsx`：
  2 个 `externalLink` 部件、`<externalReferences>` 存在、**3 条 `[1]` 公式**
  （实测 W152/W153）。但毒公式位于 `债券发行发生额` 的 W152/W153，
  而模板校验区域只覆盖 `H6:J83` 等——**毒公式在校验区域之外**，
  所以本仓库“只移植校验区域”的路径不会把它带入副本。

**结论**：本仓库是“范围隔离”侥幸避开，不是管线安全。模板作者若把一条带
`[N]` 的规则写进校验区域，或外部表导入后索引错位，缺陷立即触发。

## 四、旧管线副本为何干净（122/129 可开）的机制

排查 `formula_region_writer.py`：**零处** `[N]`/`externalLink` 处理，
公式原样写入。所以不是代码归一。

实测 openpyxl 3.1.5 读写周期（对毒模板保存后检查）：

- `xl/externalLinks/externalLink1.xml` 与 `_rels` **保留**；
- `<externalReferences>` **保留**；
- 公式 `[1]` 前缀 **保留**。

即 **openpyxl 不剥离外链**（与“openpyxl 天然剥离断链外链”的常见假设不符）。
链接与引用成对存活 → 文件内部自洽 → 能打开。旧管线的安全性来自
**校验区域范围隔离**（毒公式在区域外），不是 openpyxl 归一，也不是显式代码。

## 五、修复口径（与 Rust 实现一致）

对工作表 XML 的 `<f>` / `<formula>` / `<c:f>` / `<definedNames>` 四类上下文剥离
`[N]` 前缀——**仅当 N 后的表名存在于本包 `<sheets>`（本地已导入）时剥**；
指向真正外部簿的不动。带引号 `'表名'!` 与裸 `表名!` 两种变体都覆盖，
并兼容表名的**字面 UTF-8 与 NCR 实体**两种编码（openpyxl 保存会把中文写成
`&#38598;`，不兼容会漏修——本次实测踩过）。

拒绝“保留外链定义”方案：保留虽可让 Excel 打开，但重算会回落模板缓存的外部旧值，
审核结论将基于错误数据快照。剥离后公式指向本次导入的本地表，与旧 audit 结果一致。
真·无关外链（目标表未导入）剥离后重算为 `#REF!`，按审核异常口径捕获，
优于整文件拒绝打开。

实现：`core/src/base_audit/excel_open_repair.py::_strip_dangling_external_refs`
（`fix_external_refs=True` 默认开）。接线：

- Windows `handle_formula_copy`：DIRECT_OOXML 写入后、COM 打开前剥离
  （`fix_quotes=False, fix_panes=False`，只做本类）；
- UOS native `handle_formula_copy`：openpyxl 写公式后、LibreOffice 重算前剥离。
