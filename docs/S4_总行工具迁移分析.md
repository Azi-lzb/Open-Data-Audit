# S4 总行工具迁移分析

> 本文是对总行工具的只读源码审计和迁移方案，不包含业务实现、界面实现或测试数据。统计口径来自本机审计副本；未运行宏，未在 Excel/WPS/LibreOffice 中打开或计算，未保存原工作簿。外部实际机构名单、报文和校验规则值均不写入本文。

## 1. 结论与范围

总行工具是一条包含“机构目录维护 → 单家/汇总报文导入 → 当前期和上期数据管理 → 条件筛选及汇总 → 固定表校验 → 外部规则导入 → 分机构再校验 → 报告和 XLSX 输出”的完整采集加工流程。它不只是 Excel 求和程序：机构身份、报送状态、文件来源与更新时间、黄色/红色单元格、隐藏列、上期启用状态、工作表位置和宏提示共同构成了当前行为。

主要迁移结论：

1. 数据读取、机构目录、文件识别、筛选、汇总、报告整理和规则配置检查都可以放在 `core/` 中实现；工作簿的 OOXML 可用静态解析处理，`openpyxl` 适合通用表格读写，但不负责计算公式。
2. 当前工作簿有 25,794 个公式单元格和两个 VBA 自定义函数，宏还依赖 `Application.CalculateFull`、公式结果、单元格格式查找、事件、选择、文件对话框和 `SaveAs`。迁移必须明确实现纯 Python 的公式/规则计算链；不能把 `openpyxl` 成功读写或语法解析通过当成已完成计算。
3. 外部填报程序中的完整校验规则源未包含在本次审计材料内。现有程序要求从特定填报 XLSM 导入，并把部分跨期公式保存在隐藏公式库；在获得正式来源、映射和期望结果前，不能声称规则覆盖完整。
4. 季报完备率是从导入报文中解析并转存的来源字段，不是汇总程序计算出来的指标。迁移不得将其补成固定值；外部平台计算完备率、强制提交等人工操作不属于 S4 自动流程。
5. 可疑 VBA 条件、导入版本提示与实际判断不一致、报表频度解析不一致等问题均列为待确认行为，不在本轮审计中修正。
6. S4 对正式启用的未知机构、未知/无法解析的规则、未支持公式函数和结构不匹配必须阻断相关导入/校验/输出，并逐项报告对象、来源、原因和处理方式；不能提示后继续静默漏算。

本轮仅覆盖 `地金工具/总行工具/地方金融组织报文汇总程序20240806.xlsm` 和已存在的 `VBA_Export`。使用了用户提供的季中操作笔记理解人工步骤；未把其中的内网地址、路径或 IP 复制进本文。其他 S4 工具、外部平台操作和其他业务系统不在范围内。

### 4.2 公式单元格与规则数量口径

对 XLSM OOXML 公式和工作表做了只读静态统计，并用 `openpyxl.formula.Tokenizer` 对 25,794 个公式单元格解析：

- `再校验`中的 21,246 个公式单元格拆为 H/I 基础列 8,106 与 K:X 校验槽 13,140。K:X 按列的公式槽数依次为：K 813、L 196、M 14、N 182、O 55、P 0、Q 34、R 110、S 69、T 3,347、U 7、V 3,762、W 2,306、X 2,245。

- Tokenizer 按 `FUNC OPEN` 标记计数并区分字符串常量。当前工作簿只有两个自定义函数：`校验社会信用代码` 11 个调用位置，`比较前本期客户名称变化数量` 2 个调用位置，共 13 个。引号内的校验提示文字不是 UDF 名称。

## 5. 迁移风险与待确认行为

### 5.1 纯 Python 计算边界

`openpyxl` 可读写单元格值、格式、公式文本、表结构和校验设置，但不重新计算公式。当前流程靠 Excel 执行导入的公式和固定表公式，`模块5.bas:175-320,1031-1041` 还显式调用完整计算后再读结果。S4 禁止依赖 Office 运行时，因此实施前须选定并验收以下一种路径：

1. 把已盘点且业务确认的可移植公式转换成受限、可审计的规则 DSL，在 Python 中逐规则执行；或
2. 实现经过独立测试的 Excel 函数兼容执行器，只接受明确支持的函数/操作符；遇到外部公式中的未知函数、引用范围或语法时明确失败，不跳过。

无论采用哪条路径，均应将规则输入、规则来源版本、当前/上期快照、触发与跳过原因、错误值和说明存成可回溯的执行记录。无法仅靠公式解析覆盖的 Office 颜色/格式查找、隐藏状态、对象、控件、事件和对话框应转为显式字段和普通 UI 操作，不进入公式引擎。

需要独立测试并显式约定的 Excel/VBA 差异：

- `ROUND` 的负数与半数边界不能依赖 Python 内置 `round`；数值精度、金额小数位和错误传播需用独立黄金断言。
- 空白单元格、公式返回空串、数值 0、文本数字、空格文本、Excel 错误值在 `ISNUMBER`、`VALUE`、`SUM`、比较、空值判断及报表输出中的语义不同。
- `EXACT` 区分大小写，普通 Excel 比较通常不区分；`TRIM`/VBA `Trim` 与 Python `strip` 对 Unicode 空白也不能直接视为相同。
- VBA 的 `And`/`Or` 不短路求值；Python `and`/`or` 会短路。不得只将源码条件逐字翻译后就宣称等价；公式中错误表达式的求值顺序同样要设测试。
- 文件日期/周期、文本日期与 Excel 日期序列、数字格式显示、导入的文本型数值需要指定统一转换策略，并保留原始输入用于诊断。

| 错误与再校验报告 | 合成已报/未报、选中/未选中、不同频度指标、说明格式缺失、再校验无错/有错和主库缺列 | 从独立错误台账生成预期报告行；按机构 ID/指标 ID/错误类型比较条数、顺序和字段来源。确认完备率仅传递来源值。 |
| 输出与回填 | 按确认后的文件协议生成 XLSX/XLSM 候选、选择已有汇总结果回填、文件名冲突、空结果/部分失败 | 校验已确认的扩展名、工作表/宏结构、字段/文本格式、回填映射和原文件哈希；确认前不预设剥宏或改变交付格式，不覆盖输入，不伪造外部平台状态。 |

完整测试之前必须补齐经授权的外部填报程序版本样本、有效规则和历史规则源、机构目录 schema、报文输出 schema、固定模板版本、当前/上期关系和至少一套人工认可的期望结果。样本缺失时可以验证解析器和拒绝路径，但不能声称业务规则全覆盖。

## 8. 迁移前置门槛

1. 业务确认单家报文是否只支持季报、最低填报程序版本是否硬性校验，以及两个可疑筛选条件的旧行为。
2. 提供并确认外部规则文件来源、版本、适用频度、跨期公式的启用逻辑和完整指标映射；本次只确认代码读取方式，未证明外部规则覆盖。
3. 为导入结构、指标身份、目录字段、当前/上期快照、完备率来源和失败处理建立稳定 schema；所有配置检查只读。
4. 选定纯 Python 公式执行路径，并列出函数白名单、错误值/空白/文本/舍入/日期语义。正式运行中公式解析失败、规则不支持、数据身份缺失必须阻断相关功能并逐项报告对象、来源和原因。
5. 先完成最小公开合成测试和独立期望值，再用私有真实配置/获批真实样本完成人工黄金对拍及业务验收；合成测试不能替代真实规则覆盖。按 `rules/07_测试与发布.md` 回归受影响系统；报告核对实际导入规则数、已执行数、失败数和跳过数，数量差异逐条可解释，正式运行中未解析/未支持项目必须阻断相关功能。
6. 编号、公开空表头与真实本机配置按 VERSION_MANIFEST、`rules/06`、`rules/10` 复核后再开始实施。本次审计未修改版本、配置、代码或原工作簿。
