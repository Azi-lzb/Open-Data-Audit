# S4 地金：纯 Python 架构与伪数据验收设计

日期：2026-10-14。状态：分析与实施方案，尚未实现业务能力。

本轮范围是查证两套工具、确定迁移架构与验收方法。本文中的目录、接口、配置和测试均为拟议设计，不表示已经交付。原始 XLSM 与导出 VBA 只读；本轮未运行宏、未保存来源工作簿、未生成验收数据，也未进行真实业务对拍。本文不包含真实机构记录、正式规则表达式或阈值。

## 1. 决策与边界

1. S4 生产运行只使用 Python。不得依赖 Excel/WPS COM、VBA、ActiveX、LibreOffice/UNO 或办公套件重算；安装与运行验收包含无 Office 环境。
2. openpyxl 负责静态读写；必要的固定 OOXML 保留由明确、可验证的包级变更完成。公式文本与旧缓存只作为来源证据，不作为本轮计算结果。
3. 每类原业务能力建立配置模型、读取器、检查器、执行器和验收用例。隐藏工作表、注释菜单、辅助过程不因名称或可见性被自动删除。
4. S4 业务独立放在 `core/src/base_audit/systems/s4_dijin/`。禁止导入或复制 S3 业务模型、比较器、规则引擎、公式后端；“与大集中比较”的大集中数据是外部输入，并不因此归入 S3 执行链。
5. 已稳定且无业务口径的公共日志、文件选择、路径检查、取消任务等基础设施按契约复用。S3 内可能可通用的能力只列为未来抽取提案；如需抽取，另设变更范围、兼容证明及 S3 回归，不混入 S4 首轮迁移。
6. 正式启用规则必须可编译、可取数、可执行，或者明确阻断对应功能。未支持不等于不触发；检查不回写、不自动纠错、不静默默认零。
7. 原业务文件不覆盖。报文、反馈和错误信息库的更新交付为新副本；其接收系统是否接受新副本和文件名，需要业务验收。
8. 现有 S1/S2/S3 业务契约不变；S1/S2 默认开放、S3/S4 默认关闭，本机 `data/开发设置.json` 与“开放”标题连击 5 次后的开发口令入口保持当前契约。未来开发解锁不能绕过业务能力、配置或数据门禁；当前 S4 仍只提供预览页。

这些是用户本轮明确的 S4 技术约束。现行规则中“需要原生重算时进入 Office”的通用选择不能用于 S4；无法证明可用纯 Python 保留语义的能力先明确阻断，记录未迁项和证据。

## 3. 业务能力清单与阶段划分

操作笔记中的业务链为：外部平台人工审核/导出两期数据 → 总行构建两期数据、名单与频度 → 加载上期汇总报文 → 本期汇总/批量汇总/错误报告/再校验 → 省行跨期/基础数据一致性核对 → 接收反馈说明 → 外部平台人工提交。外部平台审核、强制提交以及人工源数据处理是人工依赖，不自动登记为 S4 能力。

笔记明确的中间交付物至少包括：批量汇总数据表、汇总季报、再校验报告、跨期校验结果、两套数据一致性结果。流程模型必须登记每项来源、前置状态与下一步骤用途。部分报告历史上由人工复制工作表保存为 XLSM，需验证接收方实际依赖是工作簿结构还是宏；不能仅保留扩展名便称兼容。

省行生成的输出模板还含由配置注入的离线宏操作，属于实际业务能力。纯 Python 迁移必须设计完整往返：S4 内置导出/接收/选择复制/合并等命令 → 无宏反馈模板 → 人工填写/传递 → S4 回传检查与说明接收 → 新结果副本。命令、可填写区域、不可变身份/时期、模板协议版本、重复回传/冲突和原说明保留均需立约。这会改变历史上依赖文件内菜单的操作体验和部分格式，必须明确列为待业务确认的迁移契约，不能隐去宏后宣称工作流不变。

历史操作中的反复清空/重导入可由两个独立、不可变的时期快照和显式流程计划替代，但必须保留本期/上期/名单/频度与汇总范围的业务含义。未知机构不能自动加入合法清单。汇总季报的源版本号与完备率是人工业务确认项；已见总行程序将报文 J2 的完备率复制到机构名录 M 列，未计算或强制改为满额。没有可验证计算与确认依据时留待核定，不能自动写成“全部完成”或伪造满额完备率。

当前正式组件清单未登记 S4，不提前修改 `VERSION_MANIFEST.json` 或占用正式 `S4-Fxx/S4-CFG-xx`。以下使用候选能力名，待来源台账与业务范围确认后登记。

## 4. 独立核心架构

```text
共享 WebApi / 两外壳
        │ S4 请求、进度、取消、结果
        ▼
s4_dijin/service.py
        ├─ importers/       来源协议识别、静态读取、原始类型/坐标
        ├─ models.py        记录身份、数值状态、配置、诊断、结果
        ├─ config/          来源适配、配置读取、数量台账
        ├─ compiler/        token、规则/表达式 AST、能力检查、依赖计划
        ├─ semantics/       数值/文本/日期/单位/缺值的显式契约
        ├─ operators/       已验证业务算子与自定义函数
        ├─ flows/           汇总、再校验、跨期、跨系统、反馈各业务流程
        └─ exporters/       结果表、报文副本、错误与冲突报告
```

目录按职责命名，不按工具版本建多套核心。总行与省行输入适配可分目录，公共业务模型只在 S4 内维护。流程不可隐式调用某个工作簿活动工作表或全局 Excel 状态。

架构验收检查 S4 的直接及传递业务依赖：不得触达 S3 包、Office 求值器、`excel_com.py` 或 Office/UNO 执行适配器。共享应用仍可服务现有系统，但 S4 请求的准备、计算、导出及异常回退均不能启动 Office、外部程序或宏。公共设施如夹带原系统业务语义，应留在原系统，不能因位于公共目录就复用。

运行顺序固定为：只读来源快照 → 输入协议校验 → 配置加载及数量账 → 同一编译器体检 → 数据身份/单位/引用审计 → 不可变执行计划 → 执行 → 结果结构检查 → 临时文件写出及重开 → 正式新副本发布。

快照包含来源指纹、协议版本、工作表/名称/公式文本索引、必要静态值及已证实承载业务信号的底色/批注/隐藏状态，不持有 Workbook 或文件句柄。输入数据采用不可变记录与显式索引；批量文件读取顺序、规则顺序、机构/指标排序、说明合并顺序均进入计划，避免字典或系统区域设置导致结果漂移。

样式信号分为源工作簿已有标记与本次 Python 求值结果的展示。读取总行报告所需的已有底色是静态协议解析，不等于执行条件格式或校验公式；若文件需要重新计算该标记，应由已迁移规则计算后明确生成。不能把条件格式 XML、旧缓存或任意黄色单元格直接推定为有效业务错误。

### 4.1 核心数据契约

| 对象 | 最少字段/约束 |
|---|---|
| `SourceRef` | 来源角色、匿名/本机文件 ID、工作表、原行/列或单元格、源指纹；定位与业务键分开。 |
| `RecordKey` | 来源协议规定的机构身份、指标、时期、频度和必要维度；文本保存前导零。各功能指定所用维度，不照搬 S3 八段键。 |
| `CellValue` | 原始值、原始单元格类型、规范类型、存在性、解析状态、数值/文本、单位；区分缺失、空白、零、文本、Excel 错误。 |
| `SourceSignal` | 信号种类、来源坐标、静态底色/其他原标记、协议解释、来源有效性；与本次规则结论分别保存。 |
| `RuleDefinition` | 稳定 rule ID、来源坐标、规则族、启停、作用域、输入引用、表达式/动作、精度/单位/缺值策略、输出目标和语义契约版本。 |
| `CompiledRule` | 类型化 AST/已登记算子、依赖、函数签名、支持状态、输出类型、来源追踪；不能装载任意 Python 或 shell 代码。 |
| `ExecutionResult` | rule ID、记录键、状态、原因、取数状态、标准化值、单位/精度过程、判定、说明、源坐标。 |
| `RunReport` | 输入/配置指纹、能力与协议版本、规则统计、执行统计、诊断、取消状态、输出清单；不在公共日志泄露原业务值。 |

重复键不得默认覆盖。不同流程原本存在聚合或覆盖语义时，由相应契约明确，记录贡献项及顺序；未证明允许时阻断。过滤后被排除的记录、单边存在、优化机构、停用跨期、日期/频度不适用均有计数和原因。

### 4.2 API 与运行状态（拟议）

未来统一 WebApi 提供 S4 方法，两外壳调用同一实现，名称以接口评审为准：

| 方法 | 请求 | 响应与约束 |
|---|---|---|
| `get_dijin_capabilities` | 无业务数据 | 已实现能力、已验收状态、所需输入角色和协议；与开发入口状态分别表达。 |
| `check_dijin_config` | 能力、配置路径、协议/语义版本 | 只读诊断及规则账；与正式运行共享 loader/compiler，不隐式迁移或写回。 |
| `inspect_dijin_inputs` | 文件角色、时期/频度、配置引用 | 结构/身份/引用问题与可执行计划摘要，不把检查当已完成运行。 |
| `start_dijin_run` | 能力、各输入角色、配置、时期、输出目录、显式业务选项 | 接受后返回 run ID；后端再次检查开放/能力/配置及输入指纹，冻结选项，禁止仅依赖前端按钮。 |
| 反馈模板导出/接收动作 | 模板种类、数据身份/时期、反馈文件、合并策略与目标新副本 | 通过统一 S4 请求执行；不注入宏、不传入任意代码，接收前验证模板协议、身份及可填写范围。 |
| `get_dijin_run` | run ID | 状态、阶段、进度、分级诊断和最终输出清单；无源内容/密码泄露。 |
| `cancel_dijin_run` | run ID | 取消请求，阶段边界安全停止；不能发布半成品为正式结果。 |

状态：`IDLE → CHECKING → READY → RUNNING → EXPORTING → SUCCEEDED`；检查失败为 `BLOCKED`，执行错误为 `FAILED`，用户取消为 `CANCELLED`。`READY` 不表示真实业务已验收，`SUCCEEDED` 仅表示本次计划完整执行并成功发布结果；业务规则不触发也可能成功。

输出到同目录临时副本，经结构和重开验证再提交正式结果。预先检查输出与所有输入的规范路径/身份冲突、同名输出和写权限；取消或失败保留可辨认的诊断，不登记正式成功产物。输入/配置检查后变更需要重新加载与体检。

## 5. Excel/VBA 语义与公式迁移契约

纯 Python 目标必须保留业务语义，不能把任意 Excel 公式套入通用、不完整公式引擎后宣布等价。允许的是按实际来源清单迁移出范围明确的业务语言与算子，并为每项写可独立核对的行为契约。

| 语义 | 必须明确的契约 | 典型验证 |
|---|---|---|
| 数值解析 | 工作簿数值、文本数字、VBA `Val`/`CDbl` 前缀解析、科学计数、空白/错误的不同路径 | 合法与非法前缀、非数字、尾部字符、布尔/错误值、零与负数；转换失败不静默消失。 |
| 数值表示 | 来源 Double 运算与 Python Decimal/浮点可能不同；按算子选定表示、精度和比较策略 | 半舍入、负半舍入、连续运算、取消相减、小量与大数；不能以“Decimal 更精确”自行改变结论。 |
| 舍入 | VBA `Round` 与工作表 `ROUND` 分开登记，包含负位数、先舍入再比较/后舍入、容差单位 | 边界三点、两种舍入分歧、源公式精度包装和回退差异。 |
| 类型与逻辑 | 比较时文本/数值/布尔类型转换、空值、函数返回类型、IF 分支及 AND/OR 的错误传播按具体来源契约定义 | 除零、错误分支、混合类型比较、文本返回的 UDF；不能直接使用 Python truthiness 或短路行为代替 Excel/VBA。 |
| 缺值与零 | 存在零、不存在、空字符串、文本、错误、成本类保留零等按来源函数分支立约 | 同一数值但存在性不同的成对案例；旧源错误降零列为待确认差异。 |
| 文本与代码 | `CStr`、Trim、引号/前导单引号、大小写、前导零、后缀取机构代码、重复名单 | 字符串身份与显示文本分开；不得对所有字段全局去引号/去空格。 |
| 日期与频度 | Excel 日期系统、来源标题日期、月末/季末/年末、上期日期选择、跨期启停 | 月界/年界/闰年、非月末、来源日期冲突和频度不适用。可疑旧日期算法单独确认。 |
| 单位 | 两侧原单位、运算单位、输出单位、阈值单位、百分数/百分点与计数 | 单位等价转换、百分数输入表示、未知单位、转换前后边界不变。 |
| 正则/查找/聚合 | VBA 正则与 Python 差异、大小写、完整/部分匹配、字典覆盖、查找优先级 | 同键多记录、匹配多项/零项、顺序、非法表达式、带文本的聚合。 |
| 筛选与统计范围 | 类别/地区组合、合法与已导入机构、指标汇总属性、两期同范围、参与机构数、精确零清空 | 数字文本与数值分流、无参与项、正负抵消、范围变化、跨期关闭、聚合为零后空白输出。 |
| 样式业务信号 | 已有 Interior 底色与条件格式显示、颜色编码和源有效性不同；来源解释必须明确 | 同值不同底色、相同底色不同机构范围、颜色主题/索引、错误信息库合并、未证明标记新鲜性。 |
| 自定义函数 | 参数类型、返回类型、错误行为、文本/数值混合返回、调用上下文 | 信用代码校验、客户名单变化等按函数登记，使用独立期望值。 |

### 5.1 支持矩阵与编译

公式来源分别登记：内嵌公式库、配置规则、校验关系导入、模板公式、自定义函数、跨系统取数表达式。提取函数、运算符、引用形式、名称、错误常量及调用上下文，标记：`SUPPORTED`、`UNSUPPORTED`、`AMBIGUOUS`、`INVALID`。支持项必须附语义契约和测试编号，不能仅凭解析成功标记支持。

编译器只允许显式批准的语法：类型化常量、业务取数引用、已登记运算符/函数与固定返回类型。AST 处理引用、精度包装和单位转换；不通过反复字符串 replace 或 `eval` 修复执行。空槽继承、名称作用域、跨表引用和规则级适用范围均有显式规则。

按使用路径划分公式：用于取原始数值、业务判定/计算、汇总/报告元信息、界面/展示。每个正式结果的依赖闭包都需要受支持的计算契约；静态工作簿大量公式可能是重复展示或辅助，不应逐单元格造一个迁移功能。源数据字段若实际为公式，不能绕过闭包审计仅取缓存；无法求出当前值时阻断依赖它的结果。

外部规则导入先做来源协议、指标清单及顺序兼容检查，再提取到规则模型、登记去重/合并/启停关系，最后走同一体检链。任意外链、动态引用、未登记函数、循环依赖、未知名称或不能证明取数范围的公式不得进入正式计划。静态模板中不参与结果计算的展示公式可以作为文本保留，但不得宣称已重算或采用旧缓存作结论。

数字精度包装、零替代、旧回退行为不能自动“优化掉”。每项注明是复刻、用户确认修正或未支持；缺少独立证据时保持阻断。移除辅助单元格只是实现手段变化，必须证明 Python 结果与其业务契约一致。

旧工具解析失败后排除规则并继续的路径与 S4 执行性硬约束冲突：S4 必须在正式结果产生前列明失败规则并阻断。这是本轮已要求的技术契约，属于明确记录的行为差异；不需另为“是否继续漏跑”设计可选模式。其他可疑业务阈值或公式修改仍需按业务确认流程处理。

### 5.2 数量与执行性守恒

迁移台账至少记录：来源指纹/版本、源工作簿/模块/表/行、原数量、正式/样例/废弃/待确认、启停数、新 rule ID、拆合关系、Python/配置落点、语义支持状态、测试与黄金证据、差异及确认依据。不要把 S3 历史规则数量用于 S4。

三种统计分别计算：

- 来源对账：源规则数 − 有证据排除项 ± 确认拆合/业务变更 = 新配置承载数量。
- 编译账：启用规则数 = 可执行规则数 + 明确阻断规则数；有阻断项时不执行该能力正式结果。
- 本次账：计划中的规则/作用域实例 = 实际已求值实例 + 有原因跳过实例 + 失败实例。未触发、跳过、失败不可混算。

本轮省行静态配置计数仅为候选盘点：

| 配置族 | 按已见空启停列得到的候选行数/源数据行数 | 验收限制 |
|---|---|---|
| 复杂校验 | E 列空：225 / 369 | 需核对 loader、频度、作用域拆分、编译失败与表达式实例。 |
| 特殊指标 | J 列空：1,071 / 3,856 | 需核对动作、空业务字段、规则拆合及注册结果。 |
| 指标参照 | F 列空：3,964 / 4,055 | 参照行不等于独立规则，需核对其实际取数/过滤路径。 |
| 跨大集中参照 | B 列空：1 / 12 | 需核对映射、两侧表达式、作用域及实际可执行状态。 |

这些数字不是正式启用数、成功编译数或本轮通过数，不作为生产上限。后续由正式 loader 分支、显式启停语义和迁移拆合关系完成数量账；公文档不复制其具体规则行。

规则结果使用 `TRIGGERED / NOT_TRIGGERED / SKIPPED / UNSUPPORTED / ERROR`；停用规则另记 `DISABLED`。`SKIPPED` 要有日期、频度、机构范围、前提不满足等可解释原因，不用于吸收解析或运行错误。

## 6. 配置与公开/私有数据边界

配置按业务职责组织候选 schema：输入协议、机构/指标参照、参数与单位、特殊动作、复杂表达式、跨系统取数、警戒区间、反馈/错误库映射、总行校验关系及自定义函数绑定。来源里的“更新日志”等业务参数显式映射，不能因工作表名而丢弃。

schema 包含稳定编号、启停、作用域、类型、单位、精度、缺值策略、源映射和协议版本；版本权威仍在 MANIFEST，不在工作簿添加版本信息表。正式 schema 确定前不改现有配置册、不提前生成 S4 配置。

现成测试配置逐文件复用 `resolve_test_config()`：先 `config-real/`，缺失才 `config/`；默认快照沿原相对路径单独选择。公开回退文件只有空表头时，报告缺少正式规则，不能写成完整业务验收。输入/配置只读，错误场景先复制到临时目录。

生产配置解析也应显式记录实际路径来源：用户明确绑定优先；自动寻找采用已确认的私有/公开规则。不存在、空配置、缺版本或错误 schema 必须可诊断，不自动复制旧配置或猜测模式。

公开仓库仅保存设计、schema/空表头、通用算子测试代码、匿名最小样例生成逻辑和人工核定的非业务期望值。正式规则、真实参照、来源拷贝、伪数据生成文件、黄金输出、差异报告及运行证据放在 `config-real/` 或 `test-output/s4_dijin/` 等明确忽略的本机位置。私有规则驱动生成物即使全部数值虚构，仍可能泄露指标/机构映射和规则，不得公开。来源目录当前未跟踪，本文不将它纳入提交范围。

## 7. 确定性伪数据与独立验收

目标是证明规则进入执行链、取数和边界正确，并验证流程与文件契约。伪数据不替代真实配置/真实格式/历史业务结果验收，不能证明尚未查明的业务口径。

### 7.1 生成方法

输入为已编译规则清单、独立语义规格、候选输入协议及显式场景计划。输出为多组工作簿/外部数据、人工可读 case manifest、预期结果和覆盖矩阵。生成器使用固定 seed 与稳定排序，记录生成器版本、配置指纹、场景版本和文件指纹；不从真实记录扰动得到伪数据。

先由规则 AST 列出取数依赖和适用条件，再为每条规则构造最小支持数据。数据身份使用虚构机构/指标，必要的正式键映射仅留本机；信用代码等需要合法校验结构时使用专用虚构身份并明显标记。记录日期、单位、文本/数值、角色和存在性不靠随机猜测。

简单比较、差额/比例、逻辑组合、配套存在、名单及聚合分别设场景构造策略。无法自动构造的规则用人工规格；矛盾前提、不能满足的取数或不明语义登记为阻断/待确认，不用跳过伪装覆盖。生成器可以依赖生产编译器取得 AST，但不得调用生产求值器生成期望结论。

采用案例集合覆盖，不要求所有规则在一份文件同时触发。共享键/约束相冲突的规则放在不同 case set；小型单规则隔离案例用于定位，成组场景验证交互，最后运行完整业务闭环。

### 7.2 每条规则的场景义务

| 场景 | 构造与期望 |
|---|---|
| 触发 | 满足作用域/前提和引用，结果明确触发；断言 rule ID、目标身份、说明与取数过程。 |
| 不触发 | 只改变决定条件的输入，保持其他条件相同；明确不触发，不能因为取数失败“没结果”。 |
| 边界 | 阈值 T 的下方、等于和上方；扰动步长取该单位/精度契约能分辨的值，不使用任意浮点 epsilon；另测舍入前后及负数边界。 |
| 合法跳过 | 日期、频度、机构范围或前提不适用；规则已入计划，记录 `SKIPPED` 及确切原因。 |
| 负面 | 非法公式/函数/正则/单位、缺列/缺表、引用不存在/多值、重复身份、错误值、源格式冲突；期望阻断及明确诊断。 |
| 多规则交互 | 同目标多规则、同键多反馈、排序/去重、过滤后仅保留提示、跨期停用、跨系统两侧映射及聚合；分别验证反馈字典末次非空覆盖和 `zj_tip` 的追加/覆盖契约。 |
| 反馈往返 | 无宏模板导出、身份和时期保护、人工说明读取、缺列/改键/跨期误回传、重复提交、冲突、旧说明保留及新副本保存。 |

负面案例期望是可定位的 `BLOCKED/ERROR`，以及无正式输出、输入指纹不变；不得把它们合成不触发案例。规则不涉及某类边界时写 `NOT_APPLICABLE` 和语义依据，由评审批准，不从分母静默删除。

### 7.3 独立 oracle

1. **手工最小黄金值**：依据已签认语义规格，通过明确手算和人工核定列表固定期望。信用代码校验、名单变化、金额/比例、日期与舍入边界均保留推导依据。
2. **独立参考实现**：仅实现特定规则族的数学/匹配规格，独立编写，不导入生产求值器或生产算子；其自身先对手工黄金值验收。
3. **既有黄金输出**：由业务方提供或已冻结的旧工具结果可离线比对，记录来源版本、输入/配置指纹和生成条件。本轮不启动来源宏，也不要求 S4 运行时调用 Office。
4. **不变量**：换输入顺序后按业务排序结果一致；可证明允许的等价单位转换后结论一致；重复运行业务内容一致；不相干记录不影响其他机构；文本前导零保存；源文件指纹不变。仅在规格允许时使用这些关系。

新造的参考实现与生产实现一致不自动算黄金通过。两者共用 parser/AST 时需声明共同缺陷风险，并用手工黄金与非法语法独立案例验证解析语义。生成器输出的答案若来自生产引擎，只能用于调试，不能作为验收 oracle。

### 7.4 覆盖报告与通过条件

覆盖矩阵以 `source_rule_id → migrated_rule_id → semantic_contract → case_id → oracle_id → expected/actual → difference` 关联。分别报告规则数量覆盖、适用场景义务覆盖、作用域/实例执行覆盖、函数/操作符/引用形式覆盖和业务流程覆盖。

通过条件：阶段范围内全部启用规则可执行；每条规则所有适用义务已有独立 oracle 和通过案例；全部差异逐项有分类与处置；正式输出结果没有失败规则；输入/配置指纹不变；零规则/空表头不能取得正式配置验收通过。报告同时列 `passed / skipped / failed / errors`，覆盖缺口和未执行项，不能只给总通过率。

大规模性能样本另成 case set，由确定性重复/扩展策略生成。记录规模、读取/编译/执行/导出耗时与资源；结果按关键身份、值、说明及结构对小规模黄金抽样/聚合核对。性能达标数字在真实设备测量后确定，本文不预设未经证实的承诺。
