## 3. 实际使用流程与交付物边界

结合用户现有使用笔记，实际工作链是：先用总行工具再校验，再按机构类型用省行工具处理本期/上期长表，并检查结果中的说明列。跨系统一致性核对使用外部批量导出的全机构/全地区本期数据与内网平台的单表批量导出文件集合。笔记内出现的内部地址和链接不复制到本公开文档。

业务过程涉及五类交付物：批量汇总数据表、汇总季报、再校验报告、跨期结果、一致性结果。省行工具的六个活动菜单叶子只覆盖其中部分文件计算/处理环节，不应据此声称单个工具自动生成全部交付物。机构根据反馈修改源数据后，需要按受影响的链重新执行；重跑范围应由数据依赖关系决定并在未来 UI 中明确提示。

外部平台的审核退回、强制提交和平台完备率流程是人工/外部系统流程，不属于省行文件工具已证实的自动能力。生成的离线说明工作簿另有“校验完备率计算”宏入口，应将它作为反馈文件内的局部辅助业务单独复核，不能与外部平台的完备率流程合并推断。

### 长表、模板及反馈匹配细节

- 长表主流程将机构名与指标编码组合作为字典键；数值型记录通常在值非零时纳入，文字型以非空为条件；成本指标存在单独空值判断。缺值和数值零在不同路径会被折成零、跳过或作为单侧数据，不能一律等价。跨期基表读取还读取原 `错误信息库` 中的说明，生成省地金提示、再校验提示/说明、基础数据校验提示/说明等多列。
- 本期、上期日期由表格本身取值；`InitSomething_Date` 中执行面板日期读取已注释掉（`广东地金系统跨期比较.bas:1263-1273`）。批量长表流程把频度写为“季”；单机构模板流程也写为“季”。`GetFreStep` 对未知频度回退到单期步长（`4093-4110`）。这些默认/回退会改变规则筛选结果，迁移时要么保持并显式提示，要么等业务确认后调整。
- 两期比较结果的基础数组定义 20 列（`1070-1073`）；主菜单还会清理/增加检查列并按 `基本配置` 中“跨期比较输出列”数组重排（`671-674`）。单机构输出使用另一套列数组（`511`）。因此输出列不是单一固定表头，应冻结两种报告的完整字段、顺序、类型、格式和宏依赖后再迁移。
- 再校验/基础数据提示匹配时，源代码中原本用于过滤的行条件被注释，当前会纳入所有行；重复同键处理规则也不同：再校验字典写入是后项覆盖，基础数据校验提示/说明经 `AcceptCheck_jcsj_addtip` 合并。`zjy_load_sm` 对汇总报告已有内容采用保留原值、只填空值的调用方式；另一条跨期反馈入口 `kj_load_zjy` 才读取“载入提示的时候是否不叠加载入”开关来决定追加/覆盖行为。两条行为需分开用例固定。见 `广东地金系统跨期比较.bas:1801-1808,1831-1843`、`说明模块.bas:8-27,57-59,93-99,497-593`。

## 5. 规则执行、计算及高风险语义

### 数据属性、单位、精度和阈值

- `DoCompare` 针对所有非文字属性计算数值差和变幅，并把绝对值传给总阈值检查（`广东地金系统跨期比较.bas:837-847`；长表差/变幅定义在 `1127-1151`）。普通数值的变幅计算是 `(本期-上期)/上期*100`；余额/累计类、个数、百分数分别选不同面板参数，部分模式用“且/或”组合，边界以 `>=` 判断（`869-928`）。同年累计类阈值还随月份进度调整。
- **口径待确认：** 当前实现对“百分数”仍沿用普通相对变幅计算；项目 `rules/06` 明确指出若原始百分数表示比例值，跨期变化应审查百分点差而非普通相对变化。应先用业务确认的样本确定口径，不能照抄或自行修正。
- `Round`/`Abs` 出现在比较、特殊检查和跨系统表达式路径。复杂表达式在求值前根据配置包裹部分数值片段为两位 `round`；基本数据/大集中表达式在 `Evaluate` 后 `Round(...,10)`。Python `round`、VBA `Round` 和 Excel 计算在边界、区域设置、文本数值及错误值上的语义可能不同，必须以独立 oracle 对拍，不得把 openpyxl 当公式引擎。
- 单位帮助函数按若干字面标签折算（`通用.bas:321-347`）；配置中的一个单位别名与该 helper 的分支未直接对应。需确认别名、源单位、目标单位和表达式是否转换；不要通过默认 1 倍折算静默接受未识别单位。
- 总阈值检查存在疑似门控缺陷：即使指标属性选择了“个数”或“百分数”专用变化阈值，组合判断外层仍检查金额阈值参数是否非零（`广东地金系统跨期比较.bas:887-918`）。需按金额/个数/百分数配置阈值分别为零/非零的矩阵对拍；此处仅记录风险，不改变业务逻辑。

### 特殊指标与复杂校验

- 特殊指标加载器按 `特殊指标-自定义` J 列空白加载，斜杠指标编码会拆为多个目标；重复目标会累积校验项（`广东地金系统跨期比较.bas:2410-2483`）。函数族覆盖结清、增减/有变动、相等、配对存在、相除、相减阈值、整除、余额/累计发生额关系以及精度误差（`2547-3250`）。需对函数族全部分支分类，不公开配置行正文。
- 复杂校验读取 `更新日志!C1` 及规则配置，先做括号归一化、平衡检查、方括号 token 检查和八段字段槽位检查，再按目标码组织规则（`3303-3435,3437-3505`）。空标记行视为候选启用。组织和地区段含正则匹配；组织类别、地区、指标、频度等按行匹配。其他 token 字段在当前匹配过程里未全部参与过滤，需要按实际业务确认字段定义，不能因注释或未使用就静默删掉。
- 初始化时无效规则会计入错误数并着色，但 `InitComplexRef` 最终仍返回空字符串；调用者因而可继续执行，坏规则从字典中漏掉（`3336-3427`）。迁移必须满足项目硬约束：**每条候选启用规则成功注册/执行，或被逐条明确报告并阻断相应运行**。预检要复用正式 token、正则和表达式 parser，不得静默跳过，也不自动改写配置。
- 表达式以 Excel `Application.Evaluate` 求值；长表达式回退写入隐藏 `yc辅助区!A1` 公式并 Calculate；失败时再去掉圆整包装重算（`3513-3672`）。纯 Python 版必须建立可审计的表达式 grammar/AST 和独立解释器，拒绝不支持语法并报告规则定位；不得调用 Office、UNO、Excel 或 VBA。公式缓存不能作为计算结果替代。
- 复杂表达式中的缺少指标会被当作 0；已存在的数值 0 会替换成小正数；跨年累计指标在某些路径改为 0；非文字/非百分数/非个数值做单位转换（`3513-3672,4011-4053`）。这些是实质规则，触发/缺数/零值/跨年/单位需要独立验证，不能作为实现细节省略。

### 来源中发现但不擅自修复的疑点

1. `是否读取被优化的机构` 在长表主流程和基础数据跨系统模块中被设为“是”时仍赋值为 `False`，与配置名不一致；大集中路径则会设为 `True`（主流程 `1762-1765,1878`；基础数据 `270-296`；大集中 `306-340`）。三条路径行为不一致，需业务确认后确定迁移基线。
2. 警戒区间校验存在疑似把数值边界与备注列比较的代码路径（`广东地金系统跨期比较.bas:4202` 附近）；需拿人工确认过的边界样例核对。
3. 省行“报文错误信息库更改”有原文件副本/覆盖保存、反馈接收有内存修改未显式保存的问题；两者都要先固定原件保护和新文件输出约定。
4. 基础数据/大集中表达式把缺失引用折为 0、错误值使用 `ycV` 转成 0（`通用.bas:79-90`）。对格式不符、无效数值、缺少指标的情形，生产版要明确拒绝还是按历史 0 语义运行，不能沿用 VBA 的宽泛错误吞掉方式而不提示。

迁移需做双端兼容：

1. V3 服务端把说明、筛选/复制可见行、说明写回/导出、再校验和基础数据提示合并等宏动作实现为纯 Python 规则化操作及 Web UI；每个入口保留可审计的操作记录和输出副本。
2. 机构离线反馈文件优先提供无宏 `.xlsx`，列名、列顺序、机构/指标标识、反馈提示/说明列和数据类型须与既有导入合同兼容；回传后按明确键匹配，显示未匹配、重复键和覆盖结果。若业务仍要求反馈文件在 Excel 内通过宏按钮完成动作，就必须另行定义受控的 `.xlsm` 交付/兼容方式；这与 V3 纯 Python、不执行 VBA/Office 的生产约束不能混为一谈。
3. `.xlsm` 源输入可按 OOXML 静态解析。生成报告的既有扩展名行为需依样本与下游系统确认：`CMyFileTool.GetOutputFile` 当前对话框只给出 `.xls` 过滤器（`Classes/CMyFileTool.cls:129-141`），`SaveWorkbookCompat` 识别 `.xls/.xlsx/.xlsm/.xlsb`（`Classes/CMyExcelTool.cls:22-85`），但注入后的工作簿是否对各扩展名都有效不能从扩展名映射推断。不得生成无宏 `.xlsm` 并宣称保留了原离线按钮。

## 9. 迁移顺序建议与待确认事项

### 建议顺序

1. **先冻结输入/输出协议**：两种跨期报告列定义，长表、单机构模板、再校验、基础检查、基础数据及大集中导出的 schema；所有缺列/重复键/多表错误都显式提示。
2. **建配置读取与只读预检**：逐 Sheet、逐源行解析并对账；启用规则必须可执行或阻断。预检和运行共用 parser/compiler，不写回工作簿。
3. **用独立 Python 实现计算域**：落在 `core/` 的 S4 专属模块；由导入适配层承接文件格式差异，不在 shell 中放业务实现，不导入或复制 S3 业务；值标准化、数据属性、单位、期间/频度、特殊检查、表达式解释器和阈值检查均不依赖 Office/UNO/VBA。
4. **实现六个活动入口及报告/反馈合同**：先文件 API，再 UI；输入保护、输出副本、说明反馈键、重复键处理需一并落实。
5. **按第 8 节对拍，再决定潜在能力范围**：每项差异按缺陷、用户确认调整、配置差异、平台差异或未支持分类并留证。

### 需用户/业务确认

- 文件名版本 `1.2.9.6` 与工作簿内部 `1.2.9` 的正式对应版本，以及随附 VBA 导出与该工作簿的版本对应关系。
- 百分数指标的业务比较口径；是否为百分点差，而非当前通用相对变幅。
- 被优化机构开关的预期作用；三条工具路径代码现状不一致。
- 输出类型：旧版结果/反馈文件的真实扩展名与下游依赖；哪些操作必须可离线点击，哪些改为 Web 后允许回传 `.xlsx`。
- 错误信息库新副本的命名、留档及下游接收规则，以及反馈接收如何保存新结果并保留原始汇总报告；不把覆盖原始业务文件作为选项。
- 反馈重复键、覆盖/追加、合并顺序与“完备率计算”宏的实际业务口径；需区分文件内辅助和外部平台人工流程。
- 多期读取、二次校验、台账拆分、反馈菜单其他命令和指标参照维护是否纳入 S4 范围。
- 当前隐藏规则中的启停标志、单位、警戒区间可疑逻辑和复杂公式语义；业务确认前不修改、不自动清洗。

## 10. 本轮未验证项

本轮没有执行 VBA，也没有真实数据运行、Excel 对拍、生成合成文件或改写输入文件。因此当前结论是静态结构和源代码路径审计；不能证明历史日志所示结果仍可复现，也不能证明导出文本与嵌入式 VBA 项目逐过程完全一致。后续可先推进已确定的协议、静态读取与合成闭环；完整业务等价验收仍需要真实格式样例、独立黄金、正式业务口径和输出合同，不将这些缺口掩盖为已验收。
