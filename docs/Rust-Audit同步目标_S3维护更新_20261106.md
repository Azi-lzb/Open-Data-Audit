# Rust-Audit 同步目标：S3 月报、日报与比较结果维护更新

请把下列已确认需求移植到 Rust-Audit 中对应的 S3 功能。先检查 Rust-Audit 当前的 S3 结构、数据契约和配置方式，再按需求实现；不要照搬 Python 项目的内部写法，也不要顺带修改 S1、S2 或其他系统。

## 目标一：单工作簿结果可选自动打开

为生成单个 XLSX 结果的 S3 功能提供“完成后自动打开”设置，默认关闭。启用后调用操作系统对该 XLSX 的默认文件关联程序。Linux 用户可能将 WPS 设为默认程序；不得强制启动 LibreOffice，也不要把自动打开和公式重算混为一项。

适用范围为 S3-F01 比较文件、S3-F02 说明文件和 S3-F04 本期核对结果。S3-F05 会生成多份金融表单，不应因该设置一次打开大量文件。

## 目标二：S3-F02 支持月报和日报说明格式

在现有 F2 入口选择输出格式，默认月报。

- 月报继续输出原来的 8 列业务结构。
- 日报在“机构名称”后插入“地区代码”和“地区名称”两列，共 10 列。
- 机构代码保留原值，例如村镇银行仍输出 7020，不把地区代码拼进机构代码。
- 指标名称、金额、上期值、增减额和变动原因按对应列输出，日报反馈可用地区代码区分同机构的不同地区。
- F3 导入反馈时，按本项目当前实现使用机构代码、指标代码、本期数据值、上期值作为匹配键；日报额外加入地区代码，月报不使用地区代码。机构/指标代码按当前实现规范化，金额按两位小数匹配；机构和地区标识的纵向合并单元格按当前实现展开。重复目标和反馈冲突必须明确报告，不能静默覆盖。

现有样例只有月报结构，没有日报结果样例。实现后需为日报字段顺序、地区键匹配和冲突报告增加可复现验证；不要凭空声称已与历史 VBA 日报逐格一致。

## 目标三：指标名称空白与缩进可配置

导入时保留指标名称原始文本，包括首尾空白和缩进。默认原样输出；用户开启 trim 后，仅在相应输出阶段去除首尾空白，不要在读取阶段破坏原值。F1 比较结果和 F2 说明文件都遵守同一设置。

## 目标四：S3-F01 月报比较结果对齐

按业务键对齐 VBA 与 Rust 输出，再逐列比较值和 Excel 单元格类型。比较键至少涵盖业务、日期、机构代码、地区代码、指标代码、数据属性和批次；排序差异与内容差异分开报告。

### 2026.10 月报样例对拍结果

按稳定业务键及顺序复验了 3,868 条记录，Python 与 VBA 顺序完全一致。本期数据值 3,838/3,838、上期值 3,833/3,833、增减额 2,946/2,946 逐格精确相等；环比 2,905/2,911 精确相等，剩余 6 格最大绝对差为 1.11e-16、最大相对差约 8.41e-15。当前 Python 写入前按 Excel 15 位有效数字归一数据值/上期值/增减额，并按将要写出的增减额和上期值重算输出环比；精确差异仍须单独报告，不得用两位显示相同代替。

指标名称有 1,619 条原文差异，trim 后为 0，因此保留原文并提供可选 trim。VBA 批次是数值、程序原先输出文本；VBA 数据日期是 Excel 日期、程序原先输出文本。Python 已调整为数值批次和 Excel 日期，Rust 输出也要对齐这两个单元格类型。

“备注”已完成复验：VBA 与 Python 各有 306 条非空，逐行文本差异为 0。Python 按数值上下限和配置备注重建 VBA 展示文案；正向倍率区间沿用 VBA 的百分数/倍数写法，保留历史区间标签原文。Rust 应输出同样的最终备注文本，不能再追加另一套区间拼接格式。

规则范围倒查已找到 43 条额外提示的来源。VBA 的 `k复杂校验-跨期核对` 历史勾选值为 1；不过 VBA `InitComplexRef` 还要求该页规则第 3 列“机构类代码”非空才装载。Python 的兼容 8 段规则没有保留这个范围，曾把无范围的规则当作全机构规则执行。当前配置中 83 条同编号跨期核对规则有 18 条具备机构范围、65 条为空。Python 已让 LEGACY_8 通过同编号五段式规则恢复机构/地区范围，并让 FIVE_SEGMENT_V1 的“跨期核对”组遵循相同非空机构范围门槛；五段式其他来源组仍保持空范围=不限制。修改后，2026.10 月报中 VBA、LEGACY_8、FIVE_SEGMENT_V1 三方的“是否说明”30 个、“计算过程”23 个命中键集合完全一致，单边命中均为 0。Rust 应实现相同的两种 schema 规则，并在运行记录报告因缺少机构范围而未执行的数量，不能静默扩大适用范围。

规则触发对象必须按稳定业务键和规则是否命中对拍，不能只看命中总数。说明文字可按新工具表达方式允许不完全一致，但需列出差异。当前两种 Python schema 的命中键都与 VBA 一致；“是否说明”精确文案一致为 13/30。LEGACY_8 的“计算过程”文本一致为 22/23；FIVE_SEGMENT_V1 使用五段 token 展示，与 VBA 八段公式文本不同（完整文本 0/23 完全相等），但拆出的代入计算结果均一致 23/23。备注与浮点精确值是独立字段，不因说明文字容差而自动视为一致。

“说明内容”两边均为空。F2 月报说明文件选中行数为 Python 101、VBA 78；该数量来自 F2 自己的“输出说明”字段，不能用来判断 F1 规则命中是否一致。

## 验收要求

1. 对月报与日报分别验证列名、列序、数据类型、机构代码及反馈回写匹配键；月报保持兼容，日报地区字段能正确消歧。
2. 通过系统文件关联验证自动打开，默认关闭；Linux 不强制 LibreOffice。
3. 验证指标名称默认保留原值，trim 设置只影响导出结果。
4. 用同一份原始样例及同一规则配置分别运行 VBA、Python LEGACY_8、Python FIVE_SEGMENT_V1 和 Rust；确认三种规则语法的明细条数一致，并按稳定业务键对拍“是否说明/计算过程”的命中对象及命中规则。说明文案允许局部差异，需列明差异数量和示例；不能只按命中总数判等。顺序、格式、范围和浮点字段另行报告；环比精确相等须报告不等数量，不能以显示相同或容差通过代替 `=` 判等。
5. 更新 Rust-Audit 自己对应的版本、变更记录与回归测试；不要复制本项目的 `config-real/`、业务数据或结果文件进公开仓库。

## Python 侧现状与限制

Python 项目已加上自动打开、月报/日报选择、指标名称保留/trim、日报反馈按地区代码匹配，以及日期/批次类型与排序调整。S3-F01 的 LEGACY_8 和 FIVE_SEGMENT_V1 跨期核对规则现均遵循 VBA 的机构范围非空门槛；五段式其他来源组不变；未修改真实配置。当前月报运行日志记录 53 条跨期规则因机构范围为空而未执行；配置中另有 65 条同组规则行为空范围，其中部分行未通过日期或规则编译筛选。2026.10 月报中 VBA、两种 Python 语法均处理 3,868 条明细；“是否说明”30 个、“计算过程”23 个命中键集合三方完全一致，单边命中为 0。两种 Python 语法代入的计算过程结果与 VBA 均一致 23/23；文字格式按用户要求允许局部不同。备注目前 306/306 与 VBA 一致；Python 与 VBA 的数据值、上期值、增减额分别 3,838/3,838、3,833/3,833、2,946/2,946 精确相等，环比为 2,905/2,911 精确相等，仍有 6 格尾数不同。S3 回归 590 passed / 568 deselected / 5 subtests passed。当前实现是移植目标的参考，不是全部验收通过的证明。
