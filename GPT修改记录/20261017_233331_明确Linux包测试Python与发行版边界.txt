目的：明确 Linux 冻结发行包内置 Python 与 core 源码 pytest 的区别，并说明 DEB/TAR.GZ 对不同发行版的适用边界，避免把“Python 3.8+”误解成启动交付包的主机要求。

修改文件：
- `运行Linux全量测试.sh`：帮助文本说明发行包启动不依赖目标机 Python；自动发现仅在存在 `dpkg-deb` 时选择 DEB，否则查找 TAR.GZ。递归查找改用 `find -exec ls`，移除 GNU 专有的 `find -printf`。package-only 模式打印包内 Python 提示；源码测试候选环境加入项目根目录 `bin/python`。
- `run_full_test_linux.sh`：帮助文本说明 Python 3.8+ 仅用于源码 pytest；发行包冒烟不要求主机 Python，并标出 DEB、兼容 glibc TAR.GZ 与 Alpine/musl 的边界；源码测试候选环境加入项目根目录 `bin/python`。
- `shell-flask/Linux-3-测试发行包启动.sh`：移除 curl 硬依赖；HTTP 检查按 curl、wget、python3/python 顺序选择。无 `dpkg-deb` 时自动跳过 DEB，只查 TAR.GZ。明确需匹配 CPU 架构及 glibc/系统运行库。
- `shell-flask/README.md`：补充发行包冒烟脚本的 HTTP 客户端、包格式和 Linux 兼容边界。
- `core/tests/TEST_GROUPS.md`：同步桌面入口和 Linux runner 的 Python、DEB/TAR.GZ 与发行版适用说明。

技术边界：PyInstaller 冻结应用所带 Python 用于运行审核工具，不是可直接调用的 Python/pytest 解释器。因此只做包启动验收时不检查主机 Python；直接对 `core/` 源码运行 pytest 时，仍需项目支持的 Python 3.8+、pytest 和运行依赖。DEB 需要 `dpkg-deb`；Ubuntu、Debian、UOS、麒麟等 glibc 系统可按架构与共享库兼容性选择 DEB 或 TAR.GZ。不能据此承诺所有 Linux 发行版，Alpine/musl 不在当前支持范围。
