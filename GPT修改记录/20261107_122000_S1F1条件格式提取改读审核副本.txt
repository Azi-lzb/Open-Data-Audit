# S1-F01 条件格式提取改读审核副本

时间：2026-11-07 12:20（Asia/Shanghai）
范围：S1-F01 条件格式结果提取节点（Windows COM 路由）；接续 v2.7.2 的副本 Excel 兼容修复。

## 问题（用户指出的缺口）

v2.7.2 把 Excel 兼容修复挂在 copy-files（复制审核副本）节点，但 DAG 里
**条件格式提取与副本链是并行支路**：`extract-conditional-issues` 的输入端口是
`source_files`（原始报送文件），COM 模式直接 `excel.open_workbook(原始文件)`。
因此 28 类 Excel 拒绝打开的文件在条件格式节点**仍然失败**——副本修复覆盖不到它。

原始拓扑：

```
source-files ──┬──> compare-structure ──> copy-files ──> add-external ──> copy-formulas ──> extract-formula-issues ─┐
               │                                                                                                     ├─> merge
               └──> extract-conditional-issues（直接读原始文件）──────────────────────────────────────────────────────┘
```

## 实现

- 模块 `excel.conditional_format_issue_extract` 新增**可选**输入端口 `workbooks`
  （FILE_SET/EXCEL_WORKBOOK_SET，required=False）。
- DAG 新增边 `copy-files.workbooks → extract-conditional-issues.workbooks`；
  UOS native 图同样带边，native handler 忽略该输入（openpyxl 读原始文件无打不开问题）。
- Windows handler `_conditional_issues_via_service`：COM 模式（COM_DISPLAY/COM_EVALUATE）
  按原始路径对齐 copy-files 产物，**优先打开 record.audit（修复后的 v1 副本）**；
  结构比对拒绝的文件无副本 → 回退原始文件；PYTHON 模式仍读原始文件
  （无 COM 打开问题，保持与 129 份对拍基线同口径）。
- `source_file` 元数据保持原始报送文件名（结果归档口径不变）。
- 语义依据：v2.7.2 修复只规范化引号与窗格，不改规则、值与渲染，
  副本与原始文件的条件格式语义完全一致，COM_DISPLAY 真实渲染判定在副本上照常成立。
