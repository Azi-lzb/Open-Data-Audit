# S1-F01 审核副本彻底断开外部工作簿引用

时间：2026-11-07 22:10（Asia/Shanghai）
范围：S1-F01 审核副本管线；`excel_open_repair` 的 `drop_external_links`（接续 v2.7.4 悬空引用修复）。

## 用户决策与要求

1. test-data 与 Rust-Audit 的毒链接已被用户自行修复，因此本轮用用户提供的真实文件验收。
2. **暂不运行外部工作簿（外部文件）引用**——只允许工作簿内（工作表之间）的引用。

第 2 点落到实现上是：副本不应再持有任何外部工作簿依赖，只保留本簿内表引用。

## 实现

`core/src/base_audit/excel_open_repair.py`：

- `repair_audit_copy_for_excel` 新增 `drop_external_links: bool = True` 与
  `dropped_links` 计数。
- 流程：剥离 `[N]` 前缀（v2.7.4）→ 重开临时包检查**是否仍存在任何 `[N]` 引用**
  （`_ANY_INDEX_PREFIX_RE = \[(\d+)\][^\s!<>()\[\]]+!`，覆盖指向未导入表的情形）
  → 若无残留，调用 `_drop_external_link_parts`：
  - 移除 `<externalReferences>…</externalReferences>`（含自闭合变体）；
  - 移除 workbook rels 中 `Type=".../externalLink"` 的 Relationship；
  - 移除 `[Content_Types].xml` 中 `/xl/externalLinks/*` 的 Override；
  - 剔除 `xl/externalLinks/` 下全部部件（含其 `_rels`）。
- **安全闸门**：只要有任一 `[N]` 残留（例如指向未导入的外部簿），就**不删**外链定义——
  否则会让原本靠 externalLink 存活的引用变成新的悬空引用。此时 `dropped_links=0` 并在
  运行日志/结果中如实反映。
- 健壮性：`_sheet_names` 在严格 XML 解析失败时回退正则读表名（结构有瑕疵仍能修）；
  临时包重读异常时放弃断开外链、文件保持原样。

## 测试

`core/tests/test_excel_open_repair.py` 新增 3 项（合计 15 passed）：

- 无残留 `[N]` → 外链定义、关系、Content_Types、部件全部清除；
- 存在指向未导入外部簿的 `[N]` → 保留外链定义（不制造新悬空引用）；
- `drop_external_links=False` → 只剥 `[N]`、保留外链（对照/回退）。

相关回归（external_copy_fallback / formula_region_writer / native_uos / workflow）：111 passed。
S1 回归：597 passed / 13 skipped。

## 调试过程中发现并修正的三个测试侧问题

1. `_inject_formula` 传入带前导 `=` 的公式 → 写出 `<f>=INDEX(...)`（非法），修正为不带 `=`；
2. 测试脚手架把 `<externalReferences>` 放在 `<calcPr>` 之后（违反 schema 顺序）且根元素缺
   `xmlns:r` 声明 → 解析失败；已按 schema 顺序紧跟 `</sheets>` 并补命名空间声明；
3. 脚手架写了 `externalLink1.xml` 却漏了它的 `.rels` → openpyxl 读取报 KeyError；已补全。

前两项同时反哺了生产健壮性（`_sheet_names` 回退正则）。
