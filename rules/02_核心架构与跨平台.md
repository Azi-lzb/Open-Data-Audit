# 核心架构与跨平台补充

总体架构与技术优先级见 `AGENTS.md`；Excel 文件处理细则见 `rules/03_Excel与OOXML边界.md`。本文件只约束平台适配边界：

- 平台差异集中在 `core/src/base_audit/engines/`、`core/src/base_audit/native/` 和两个 shell；业务流程不得散落 COM、UNO 或操作系统判断。
- Windows 真实工作簿计算使用 Excel/WPS；COM 延迟导入，使用独立隐藏实例，不关闭用户已有的 Office，并在 `finally` 中可靠关闭资源。
- UOS/Linux 静态文件处理使用共用 core 内经过验收的 Rust/Python 后端；性能选型与引擎路由见 `rules/12_Rust优化与引擎路由.md`。真实重算的现行兼容后端为 LibreOffice Calc/UNO；缺少所需计算引擎必须明确失败，不能拿旧缓存值冒充本轮结果。
- Rust 源码与工具适配均在 `core/` 内维护；两个 shell 共用同一接口与业务契约，不在外壳复制业务实现。Windows 与 Linux AMD64 分别构建/测试原生产物，Linux 按 glibc 2.28 兼容目标验证；保留的旧 Windows/32 位/Python 目标须另核对 Rust 工具链、依赖和 ABI 兼容性。
- 平台专属代码修改后按影响范围做对应真机回归；未触及的平台边界不要求每次重复整套平台验收，规则见 `rules/07_测试与发布.md`。
