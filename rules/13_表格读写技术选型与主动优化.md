# 表格文件读取、写入与修改技术选型规范（V3）

> 文档版本：1.4-V3.1（规则版本，不是产品版本）  
> 更新日期：2026-10-23  
> 适用目标：V3 的 Windows 与 UOS/Linux；当前 Linux 发布仅 AMD64，glibc 兼容目标为 2.28。Windows 10/11 64 位为常规目标；仍由项目脚本维护的 Windows 7 兼容构建作为独立目标核验。具体系统、运行时和依赖按本项目已有支持范围声明。  
> 用途：让开发 agents 根据功能的输入、输出和保留要求确定技术；对已经适配并验收的多种技术提供用户选择。

## 1. 执行原则

本文件中的“必须”“禁止”“默认”“不支持”是执行规则。技术选型按第 2～5 节执行；第 8 节规定 V3 的接入边界，不能充当具体后端的验收证明。

同一功能分别确定读取、计算、写入、格式转换和渲染后端。pandas 是数据处理层，其实际 Excel engine 必须写明；“使用 pandas”不能作为读取器或写入器的完整选型结论。

**确定性不等于承诺所有格式都能处理。能力不足时，确定结果就是“不支持当前要求”，并报告具体缺项。agents 不得用降级输出掩盖能力缺失。**

开发和维护还必须执行本节下方的主动效率检查流程。本规范与 [Excel/OOXML 边界](03_Excel与OOXML边界.md)、[Rust 优化与迁移验收](12_Rust优化与引擎路由.md) 配合使用：本规范负责输入输出契约、操作匹配、可用后端选择与用户选项；03 负责文件结构硬边界；12 负责 Rust 候选、分系统迁移和验收顺序。用户当前指令及 AGENTS.md 的硬约束优先。

已有功能保留已验收的默认路由；变更默认路由执行第 9 节的迁移条件。新功能使用第 4 节给出的默认顺序。阅读本规范本身不授权批量重写现有功能。

### 主动效率检查流程

1. 开发、修复或维护业务功能时，先识别 `Sx-Fxx / Sx-CFG-xx`，读取实际 core 调用链，按第 2 节填写输入输出契约，并分别标出读取、规则计算、写入、Office 重算和渲染阶段。纯文档/样式任务只核对相关规则，不运行无关业务基准。
2. 检查本次功能的重复打开/保存、逐单元格 COM/UNO 调用、重复 DataFrame 构造、无必要的格式转换、缓存失效、宽泛异常回退和对象保留缺口。只检查当前功能及直接依赖，不扩展为无授权的全系统重写。
3. 发现具体热点或能力缺口时，必须主动提出技术调整方案，列明当前入口、代码或阶段计时证据、替换阶段、候选后端、格式/平台/保留项、实施范围和验收指标。未测量写明“尚未测量”，先给出测量方法，不承诺提速倍数。
4. 新增性能敏感能力按 rules/12 评估 Rust；已有 Calamine reader、Direct OOXML writer 和其他已验收快路径作为现行基线，不将其改回 openpyxl，不把原有优化报告成新增成果。尚无迁移证据时保留现行默认；候选后端经对拍与性能验收后才切换。
5. 同一契约有多个合格后端时，按系统、功能和阶段提供默认“自动”与用户手动选择，持久化设置；未验收后端不进入选项。不得为了技术齐全给每个操作加入全部库。
6. 已授权的优化和必要修复完成实现与对应验收；超出授权的跨系统迁移、输出语义或外部依赖变化先形成可审阅方案。执行分系统迁移时沿用 rules/12 的阶段顺序，不跳过 S1 公式依赖、S5 基线和真实应用对拍。
7. 交付列出默认方案、用户备选、实际测量、已执行与未执行验收。未发现后端迁移依据时说明原因并完成原任务；不得编造提速建议。
8. 每次实际修改在 `GPT修改记录/` 新增记录，格式按 rules/08；业务版本与 CHANGELOG 按 rules/11，纯规则变化不升级产品/组件版本，不写入用户版更新日志。
9. 大结果集新建写入须设峰值内存预算检查点。基准中同类 30 万行×20 列纯数据写入，Direct OOXML 峰值约 377 MB，Rust JSON 桥接路径约 1,588 MB；约 380 MB 仅作为该类负载的参考量级，不是所有输入的硬上限。候选路径高于参考量级时，技术方案必须解释原因并说明资源预算如何满足。依据：基准报告《写入结果》（`../../3.open-data-audit-benchmark/results/benchmark_report.md`）。
10. Python↔Rust 子进程与 JSON 桥接的编码、数据复制/解码、进程启动、Rust 解析、生成与压缩阶段耗时及峰值内存须分别计量，并纳入端到端结论；不得只报告 Rust 引擎内部耗时。依据：基准报告《范围与实现审计》《写入阶段耗时中位数》（`../../3.open-data-audit-benchmark/results/benchmark_report.md`）。


## 2. 先确定功能输入输出契约

agents 在实现前填写下表。已有需求、配置和代码能确定的项目直接填写；只有会改变结果且无法从上下文确定的信息才询问用户。

| 字段 | 取值和默认规则 |
|---|---|
| 操作 `operation` | 选取第 4 节的操作编号；一个功能含多个阶段时分别编号。例如“xls 时序提取并生成 xlsx”是 R01 + W01。 |
| 平台 `platform` | 记录系统版本、CPU 架构、Python/冻结运行时版本。跨平台功能分别填写 Windows 与 Linux 目标。 |
| 输入 `input_format` | 按文件实际内容识别；扩展名只用于初筛。识别不到或扩展名不匹配时停止，禁止靠改后缀处理。 |
| 输出 `output_format` | 新建工作簿默认 xlsx；修改已有文件默认保持原格式；格式转换使用用户指定格式。输出原格式不被 writer 支持时报告不支持。 |
| 输出形态 `output_kind` | `new_report` 新报表、`edit_existing` 修改已有工作簿、`format_convert` 格式转换、`render` PDF/纸张、`filesystem` 文件操作。禁止把重建报表当作修改既有工作簿。 |
| 值的口径 `value_view` | 默认 `stored`：读取文件中存储并解码的值；用户要求“显示出来的文字/金额/百分比/前导零”时选 `displayed`，执行 R04。数值 1 配格式 000 的显示值是 001，普通 str(1) 不满足该要求。 |
| 公式口径 `formula_mode` | 纯取值默认 `cached`：接受文件上次保存的结果，不承诺本轮重算；读取/保留公式文本选 `text`；同时取文本和缓存选 `text_and_cache`；要求按本轮输入计算选 `recalculate`。修改既有文件默认保留公式文本。 |
| 保留项 `preserve` | 新建纯数据报表默认保留字段、值、类型和任务指定的行列位置；不复制源版式。修改既有文件默认保留除本次变更对象以外的既有功能，先列出对象清单，再验证 writer 全部覆盖。转换默认保留目标格式能够表达的源对象；目标格式不能表达的对象执行冲突检查。 |
| 允许丢弃项 `drop_allowed` | 默认空集合。丢弃源格式不等于丢弃公式、宏、工作表或批注；每一项须由功能定义或用户明确允许。 |
| 中间转换 `allow_conversion` | 显式格式转换为 true；其他操作默认 false。读取 xls 的值不需要先转 xlsx；对 xls/xlsb 修改后输出 xlsx 必须在契约中明确该转换。 |
| 外部应用 `external_apps` | R04、R05、W04、W07、Q02、C02、P02、D01 阶段默认允许；其他阶段默认禁止。项目的纯 Python 约束或用户选择覆盖此默认。结构修改需要应用且该字段为禁止时，只能选满足同一要求的已验收静态适配器，否则停止。 |
| 应用基准 `reference_app` | 默认 `none`，表示不要求某个应用的专属计算/版面语义；要求与 Excel、WPS、LibreOffice 一致时分别指定。指定后只能使用该应用或已通过同一契约对拍的替代适配器。 |
| 用户后端选择 `engine_mode` | 默认 `auto`；手动模式写明读取、写入、转换或渲染阶段的具体后端。手动选择的执行规则见第 6 节。 |
| 规模与资源 `workload_limits` | 记录测试覆盖的文件数、sheet 数、行列数和对象数量。用户给出最长耗时/峰值内存上限时纳入契约；没有上限时不自行设置“超过某 MB 就用 Rust”等阈值。 |

保留项按实际对象列出，至少检查以下类别：公式和缓存、合并、字体/填充/边框/数值格式、行高列宽/隐藏状态、工作表名/顺序/可见性、打印设置、批注文本、批注外观、定义名称、超链接、数据验证、条件格式、表格、图表/图片/形状、外部链接、VBA、ActiveX/OLE、未知扩展部件。

对象清单必须检查原始文件。xlsx/xlsm 的部件及关系不能只以 openpyxl 已加载的对象为准，因为未支持的部件不会因此变成“不存在”。未识别的部件记为“未知”，没有覆盖该部件保留要求的适配器不得保存此文件。

### 必须先拒绝的冲突

- 要求保留 VBA/XLM 宏，却指定 xlsx 输出：停止并让用户在支持宏的格式与明确丢弃宏之间选择；默认不丢弃。xlsx 不能保存 VBA/XLM 宏，xlsm 可以保存。[Microsoft 格式说明](https://learn.microsoft.com/en-us/office/compatibility/office-file-format-reference)
- 要求输出 CSV，同时保留多个工作表、单元格格式、批注或可执行公式：停止并要求调整输出契约。CSV 字段里出现“=...”文本不等于保存了工作簿公式及其计算能力。
- 要求本轮计算结果，却禁止所有满足该公式链的计算引擎：报告不支持；禁止读取旧缓存冒充重算。
- 要求保留全部源对象，但对象清单含当前适配器未支持或未识别的部件：该适配器不合格；没有合格后端时停止。
- 文件存在宏、对象或签名，而格式转换会删除或使其失效：先报告冲突。保留 VBA 二进制项目不等于执行 VBA，也不等于保留数字签名有效性。

## 3. 路由算法与“已适配”的定义

开发新功能时，先按主表的默认顺序选取在库能力、格式和目标平台上满足需求的技术作为实现目标，然后开发适配器、补齐对应验收，达到“通过”后再交付。已获授权的开发任务应完成这些工作，不能以“还没有适配器”为理由只提交选型建议。资源预算需要性能测量证明，库文档不能代替测量。

以下六步用于正式执行已开发的功能，不跳步：

1. 解析第 2 节契约，检查冲突，识别输入对象。
2. 按第 4 节匹配操作编号；先匹配特殊要求，再匹配只读值等通用行。例如需要公式文本时匹配 R03/R05，不匹配 R01。
3. 生成候选集。后端必须同时满足：已实现适配器、该操作/输入/输出/保留项/平台已有通过的验收记录、当前运行环境可加载；存在资源预算时还须满足对应规模下的预算。仅安装了库、查到官方支持或存在函数代码均不满足此条件。
4. 手动选择：仅执行用户选定且满足契约的后端。不合格或执行失败时停止并说明原因，禁止静默换引擎。
5. 自动选择：先使用满足契约的功能默认后端；该功能未设置默认或默认不可用时，按主表的默认顺序选择第一个合格后端。顺序中的后端不合格就排除；全部排除后报告不支持或缺少引擎。
6. 执行并验证输出；第 6 节规定哪些失败允许自动重试。对本轮已判定不满足契约的输出，禁止通过更换引擎隐藏差异。

能力登记用现有配置、普通字典或静态表即可，不要求新增插件框架。每个登记项至少记录：功能/操作编号、后端与版本、输入输出格式、覆盖的保留项、系统/架构、适配器入口、验收报告或测试证据、功能默认值。

能力状态只有三类：

| 状态 | 判定条件 | 自动执行 / 用户选择 |
|---|---|---|
| 通过 | 适配器已实现，且本次契约属于已通过的验收范围 | 进入候选集 |
| 未验收 | 缺少上述验收证据；包括仅有库文档、仅有 mock、仅存在代码 | 不进入候选集；开发阶段在隔离副本上补验收 |
| 不支持 | 后端缺少本次必须能力，或目标平台没有对应实现 | 不进入候选集；报告缺少的能力 |

## 4. 功能读取、写入与修改主表

表中 `A → B` 表示自动模式按顺序从**合格候选集**选择，不要求为每个功能实现所有后端。“同契约备选”必须满足第 3 节后才能展示给用户。`原生表格引擎`、`原生文字引擎` 按第 5 节解析。

| 编号 / 功能及匹配条件 | 默认读取 | 默认写入 / 修改 / 执行 | 同契约备选 | 明确边界 |
|---|---|---|---|---|
| F01 文件扫描、按文件名重命名、排序前缀、复制、移动、归档 | pathlib / os；不读取表格内容 | pathlib / shutil / os | 无需 Excel 后端选项 | 文件字节必须保持一致。文件冲突、占用和跨卷移动按功能定义处理。 |
| F02 按单元格内容重命名文件 | 存储值执行 R01；显示文字执行 R04 | 文件名修改执行 F01 | 沿用读取阶段的合格备选 | 不对工作簿调用 save；不通过重存工作簿完成文件名变更。 |
| R01 只读值、sheet names；不需要格式、批注、公式文本、原始错误类型 | xlsx/xlsm：Calamine 系（Rust crate；`python-calamine` 绑定须经同契约验收）→ openpyxl；xls：Calamine → xlrd；xlsb：Calamine → pyxlsb | 不写源文件；生成结果另匹配 W01 | 此行列出的合格 reader | Calamine 只读。必须保持数据位置及声明的空白/零/类型语义；禁止把失败或 Excel 错误替换成 0/空白。 |
| R02 按单元格坐标读取值与合并区域；xlsx/xlsm/xls | xlsx/xlsm：Calamine → openpyxl 普通模式；xls：Calamine → xlrd 的合并信息适配器 | 不写源文件 | 已验收的 Direct OOXML reader 只用于 xlsx/xlsm | Calamine 合并接口返回 None 时表示该路径不提供信息，必须报告能力不足；不能解释为“没有合并”。xlsb 的合并请求执行 R05。 |
| R03 读取 xlsx/xlsm 公式文本、单元格类型、批注文本、样式、打印设置或名称 | 现有已验收 Direct OOXML 元数据 reader → openpyxl；选择 openpyxl 时公式文本用 data_only=False、批注用 read_only=False；取文本与缓存时从同一只读源提取两种视图 | 不写源文件 | 覆盖所需部件的已验收 Rust 元数据适配器 | Direct OOXML 只在本次所需部件均已实现时合格；openpyxl read_only 模式不能读取批注。区分文本“#N/A”和 Excel 错误时必须保留原始类型信息。 |
| R04 读取应用实际显示文本；或要求与某应用显示一致 | 原生表格引擎读取应用显示结果 | 不写源文件 | 已针对目标数值格式/日期/语言环境验收的显示值适配器 | Calamine 返回值加 str()、openpyxl 的 value 均不能默认作为应用显示文本。 |
| R05 xls/xlsb/ET/ETT 需要 R01 未提供的公式文本、合并、批注或结构 | 原生表格引擎 | 不写源文件；若 allow_conversion=true，则先执行 C02 再按目标格式读取 | 能提供本次全部字段的已验收格式 reader | 只读值成功不构成这些元数据已支持的证明；不允许转换或无合格应用时报告不支持。 |
| W01 时序、宽表、比对、校验、值提取等生成**新的**纯数据 xlsx | 来源值执行 R01/R02 | 默认沿用现有已验收 Direct OOXML writer；候选顺序为 rust_xlsxwriter → openpyxl write_only writer → openpyxl 普通 writer | 此行合格 writer；pandas 是调用相应 writer 的数据层 | rust_xlsxwriter 只有在第 9 节的桥接与内存门槛复测通过后，才可作为自动默认候选；既有功能默认仍优先。write_only 只在适配器支持单向追加、无写后读取/修改时合格；新建 writer 不编辑已有文件。 |
| W02 修改已有 xlsx/xlsm 的单元格值、字体、边框或打印属性；不改变行列/Sheet 身份 | openpyxl 一次加载可编辑工作簿；选中其他编辑器时使用该编辑器的读取会话 | openpyxl → Direct OOXML 定点修改适配器 → umya-spreadsheet 适配器 → 原生表格引擎（仅 external_apps=true） | 此行合格编辑器 | writer 必须覆盖输入对象清单。保留公式时禁止保存以 data_only=True 加载的值视图；xlsm 保留 VBA 时必须 keep_vba=True，并验收宏项目。 |
| W03 给已有数据 sheet 追加记录；保留其他 sheet | 读取原工作簿和目标表；默认复用 openpyxl 现有会话 | openpyxl → 已验收的 Direct OOXML 追加适配器 | 覆盖目标工作簿所有保留项的编辑器 | pandas 替换整个 sheet 会改变原 sheet 结构，不能冒充逐行追加。真正删除重建 sheet 时执行 W04。 |
| W04 插入/删除行列、移动区域、重命名/删除/重排 Sheet | 修改器的读取会话 + 依赖检查 | 已证明无受影响依赖：openpyxl → Direct OOXML → umya；存在依赖或依赖状态未知：原生表格引擎 | 静态适配器已实现并验收全部受影响依赖维护时，进入有依赖场景的用户备选 | 受影响依赖含公式、定义名称、表格、图表引用、外链和打印名称。依赖状态未知时不得选静态编辑器；不自动改业务公式语义。 |
| W05 跨工作簿按值提取、合并；不复制源格式 | R01/R02 | W01；写已有目标执行 W03 | 沿用对应读写阶段备选 | 明确坐标是否保留、合并是否展开、输出 sheet 命名和字段顺序；这不是整表保真复制。 |
| W06 跨工作簿复制明确列出的基础样式、合并、行列尺寸及打印设置 | openpyxl 读取源对象 | 本功能的 openpyxl 复制适配器 | 已验收的 Direct OOXML/umya 复制适配器 | openpyxl 的 copy_worksheet 不能跨工作簿；必须有本功能的复制代码和保留清单，不能只调用该 API 声称完成。 |
| W07 跨工作簿复制整表，并保留图表/图片/名称/宏或未知对象 | 原生表格引擎 | 本功能的原生整表复制适配器 | 完整维护关系、引用和对象的已验收包复制适配器 | 不以单元格逐项复制替代该操作。原生复制后也要校验契约；没有合格适配器时报告不支持。 |
| P01 生成可直接打印的 xlsx，保留指定的框线/合并/行列尺寸/打印设置 | 要复制源格式时 openpyxl；只重建已定义版式时 R01 + 固定版式定义 | openpyxl 生成工作簿 | 同一保留清单已通过的“Calamine 读值 + openpyxl 读格式/写出”快路径 | 此功能输出 Excel 文件；无需渲染引擎。快路径不能把普通模式保留的必需项删掉；两种模式有保留差异时必须作为不同功能模式说明。 |
| Q01 读取上次保存的公式结果 | R01；需要识别缺失缓存/错误类型时 R03 或已验收的 OOXML 缓存检查适配器 | 不重算、不写源文件 | 同一缓存口径的合格 reader | 结果必须标为“文件已保存结果”。缺失缓存与合法空结果无法区分时报告缓存状态无法确认；不得宣称缓存已刷新。 |
| Q02 根据本轮输入真实重算并读取结果 | 原生表格引擎打开副本，写入本轮输入 | 显式重算 → 保存 → 关闭 → 静态 reader 取结果 | 已对完整公式依赖链验收的其他计算后端 | 重算后再改写输入/公式或清除缓存，必须重新重算。仅打开应用或设置重算标志不构成通过。 |
| C01 xls/xlsb/ET/ETT 仅迁移值到新的 xlsx，用户明确不保留源公式/格式/对象 | xls/xlsb 执行 R01；ET/ETT 执行 R05 | W01 | 同契约值迁移适配器 | 功能名称和输出说明必须写“按值重建”；不得标为格式保真转换。存在 VBA 且未允许丢弃时先检查冲突。 |
| C02 保留契约内对象的真实工作簿格式转换，例如 xls → xlsx | 原生表格引擎读取源文件 | 原生表格引擎 Save As / 转换过滤器 | 通过相同输入输出及保留清单验收的其他转换适配器 | 目标 xlsx 不能保留宏；目标格式、过滤器和是否改变公式必须列入验收。不自动转为 C01。 |
| P02 导出 PDF 或发送打印机，要求分页和字形渲染 | 原生表格引擎 | 目标引擎的 PDF/打印适配器 | 与目标应用版面契约对拍通过的渲染器 | 字体、页尺寸、缩放、页边距、打印区域、打印机环境必须记录。若要求 Excel 精确分页，不能默认用 LibreOffice 输出。 |
| D01 Word doc/docx 互转 | 原生文字引擎 | 原生文字引擎转换 | 通过本次文档对象和版面要求验收的其他转换器 | doc/docx 转换单独登记；不能由“已支持 xls 转 xlsx”推导出 Writer 转换已通过。 |
| T01 CSV 逐行读写；数据无需 DataFrame 算法 | Python csv | Python csv | 已验收的 pandas CSV 适配器 | 显式指定编码、分隔符、引号和列类型。不能把 CSV 的类型推断当作存储了 Excel 单元格类型。 |
| T02 CSV 需要 pandas 分组/连接/透视等算法 | pandas.read_csv，显式列类型 | pandas.to_csv；输出 xlsx 时执行 W01 | 同契约 csv 适配器 | 输入编码和标识码处理必须确定；禁止为同一阶段同时读成 csv 列表和 DataFrame。 |

### 主表附加硬条件

- Calamine 需要保持源单元格坐标时使用 `skip_empty_area=False`，或由适配器正确回补源区域起点；不允许直接丢掉前导空行列。
- openpyxl 只读值的模式与可编辑模式分别登记；`read_only=True` 不用于修改，`write_only=True` 不用于编辑已有文件。
- openpyxl 不负责自动维护插入/删除行列后的全部依赖；W04 必须使用表中单独的依赖条件。[openpyxl 结构编辑说明](https://openpyxl.readthedocs.io/en/stable/editing_worksheets.html)
- openpyxl 的批注读写覆盖文本，批注格式和读取时的尺寸不在默认保留范围；需要保留外观的任务不能选普通批注适配器。[批注说明](https://openpyxl.readthedocs.io/en/stable/comments.html)
- 对不在 `preserve` 中的源版式，可以不复制；对必须保留而后端未覆盖的对象，排除后端。禁止以“多数场景可用”绕过该判定。

## 5. 原生引擎按系统与格式确定

下表仍须先经过第 3 节的适配与验收筛选。安装应用不等于已验收；Linux 安装 WPS 也不等于具有 Windows COM 接口。

| 操作 / 约束 | Windows 10/11 64 位默认顺序 | 麒麟 V10 / Ubuntu / Debian 默认顺序 | 没有合格后端时 |
|---|---|---|---|
| xls/xlsx/xlsm 静态转换、结构编辑、通用重算或渲染，reference_app=none | Excel COM → WPS 表格 COM | LibreOffice Calc：转换/PDF 用 CLI；需会话控制或重算验收的流程用对应 UNO/自动化适配器 | 报告引擎缺失或该对象组合未验收，不改用值重建 |
| WPS 原生 ET/ETT | WPS 表格 COM | 仅接纳已针对 ET/ETT 输入和保留项验收的 LibreOffice Calc 适配器；缺少此登记则不支持 | 要求先用 WPS 转成 xlsx，或新增目标平台的转换适配器；不尝试 Excel 默认解析 |
| xlsb 只读元数据或转为 xlsx/xlsm | Excel COM → 已验收此格式的 WPS 表格 COM | 仅接纳已验收此输入输出组合的 LibreOffice Calc 适配器 | 要求在具备合格引擎的系统先转换；只读值仍可走 R01 |
| 输出必须仍为 xlsb | Excel COM → 已验收 xlsb 导出的 WPS 表格 COM | 本规范基线无 xlsb writer，判定不支持 | 不改变输出扩展名或偷偷输出 xlsx |
| 执行 Excel VBA/XLM，或必须遵循未获替代验收的 Excel 专属计算/对象语义 | Excel COM | 本规范基线不支持 | 请求改变运行平台或需求；不得把宏项目保留当成宏执行 |
| reference_app 指定 Excel/WPS/LibreOffice | 对应应用的已验收适配器 | 对应应用的已验收适配器；Windows COM 在 Linux 不成立 | 报告缺少对应应用；只有已有同契约对拍证据的替代器才能进入备选 |
| doc/docx 转换，reference_app=none | Microsoft Word COM → WPS Writer COM | LibreOffice Writer | 报告缺少文字转换引擎 |
| 已识别的 WPS 文字原生文件 wps/wpt | WPS Writer 原生适配器 | 仅接纳已验收该实际文件格式的 LibreOffice Writer 适配器 | 不进入 Excel reader/writer 路由 |

COM 客户端的 pywin32 必须与 Python 的 ABI/位数一致；不能把 Python 与 Office 位数不同直接判定为不支持。Windows 的进程外 COM 支持 32/64 位进程通信，是否可用由实际注册、接口和启动验收判定。[Microsoft 进程互操作说明](https://learn.microsoft.com/en-us/windows/win32/winprog64/process-interoperability)

Windows 7 兼容包按独立平台验收：以项目实际构建脚本和锁定依赖声明的 32 位 Python 版本为准，单独核对原生扩展、外部应用接口和文件格式能力。不能从 Windows 10/11 的验收推导 Win7 兼容；也不能假定 Flask 与 pywebview 两个 shell 的 Win7 覆盖范围相同。

## 6. 多后端用户选择、失败与回退

### 用户选择

- 只有一个合格后端：直接运行，界面不要求用户选技术。
- 同一阶段存在两个以上合格后端：提供“自动（默认）”和各后端名称，允许用户选择。选择范围按功能和读取/写入/转换/渲染阶段设置，不提供无能力区别的全局技术菜单。
- Calamine 直接 API 与 pandas calamine engine 同属 Calamine 读取后端；不能把“pandas”和“Calamine”展示为同级互斥引擎。
- 每个选项说明其保留范围、是否启动外部应用、已记录的性能与环境依赖。只允许同一契约的技术互换；“按值复制”和“保留格式复制”属于不同输出模式，不能混在技术选择中。
- 未实现、未验收或本机不可用的技术不进入可执行选项；已持久化的手动选择失效时，保留设置并提示用户处理，禁止静默切换。
- 持久化范围至少包含功能、阶段、输入输出格式和系统；同一平台的架构差异通过能力筛选处理。
- 用户未调整设置时使用自动默认，不在每次启动和每个文件上重复提问。

### 失败与回退

| 情况 | 自动模式行为 | 手动模式行为 |
|---|---|---|
| 执行前发现未安装/无法加载引擎，或缺少已声明能力 | 排除该候选，按第 4/5 节顺序选择下一个合格候选 | 停止并报告用户选定引擎不可用 |
| 适配器明确报告格式/特性不支持，且另一候选覆盖全部要求 | 从原始输入或干净副本重试下一合格候选，并记录原因 | 停止，展示满足条件的其他选项 |
| 文件损坏、密码/加密未处理、权限、输入/输出被占用、磁盘空间不足 | 停止当前任务并报告原因；不更换引擎掩盖问题 | 同左 |
| 输出校验差异、计算错误、缓存未刷新、超时或未知异常 | 停止，保留诊断和临时输出；不自动回退 | 同左 |

每次输出先写临时文件，通过契约验证后才提交到最终路径。覆盖用户文件必须遵循功能已有授权和备份策略。禁止对半写入结果继续回退。禁止用 `except Exception` 把所有错误归为兼容失败。

运行日志记录功能/操作编号、输入输出格式、实际后端与版本、选择原因、回退原因、读取/计算/写入耗时、失败类别和未满足的保留项。

| 格式 / 平台 | 确定规则 |

| xls | Calamine/xlrd 只读；原格式写入或保留契约的转换走原生表格引擎；按值新建 xlsx 走 C01。 |
| xlsb | Calamine/pyxlsb 只读值；需要合并、批注、公式文本或修改时执行 R05 和第 5 节。禁止从“值读取成功”推导整表兼容。 |
| ET/ETT 与 WPS 生成的 xls/xlsx | ET/ETT 是独立输入格式；WPS 生成的标准 xls/xlsx 按实际格式处理，发现 WPS 专属功能时加入 preserve 和验收范围。 |
| CSV | 没有工作簿对象、单元格格式和独立的单元格类型信息；编码、分隔符和字段解释在契约中固定。 |
| Windows 10/11 64 位 | 声明具体系统构建、CPU 架构、Python/冻结运行时和原生应用版本；原生扩展须匹配该 Python ABI 与架构。Windows 产物不作为 Linux 产物使用。 |
| Windows 7 兼容构建 | 仅在项目对应 shell 的发行脚本仍提供该构建时纳入支持范围；按实际锁定的 32 位 Python/依赖单独验收，不继承现代 Windows 的后端、扩展或 Office 兼容结论。 |
| 麒麟 V10 SP1 / UOS / Linux | 声明具体发行版本、CPU 架构、glibc/GLIBCXX、Python/冻结运行时、LibreOffice 版本与字体；只能使用对应平台产物。Ubuntu 容器验收不能替代麒麟目标机的 ABI、安装包、桌面打开和字体渲染验收。 |
| 包格式与运行时 | 区分 deb 能否安装、ELF 能否启动、业务输出是否正确三个验收项。使用系统 Python 时按锁定依赖核对其版本；冻结包使用自身运行时，不能由系统 Python 版本推断运行时版本。 |

批注、公式和对象操作的能力不能只用扩展名登记；格式相同但对象集合超出已验收范围的文件，按第 3 节排除不合格后端。

### 系统功能到实际后端的路由登记

需要提供后端选择，或新增/变更某个后端路由时，能力登记必须同时标明系统功能编号（如 `S2-F01`）、本规范操作编号（如 `R01 → W01`）、`core/` 中实际适配器入口、自动默认与允许的回退路径、适用平台/依赖范围，以及对应测试组或验收报告。这样可从用户看到的功能追溯到实际读写实现。

登记沿用项目现有的静态表、配置或适配器元数据，不新建通用插件框架；只登记实际接入或准备展示给用户的后端，不要求为所有历史功能建立庞大的重复清单。路由、默认值或能力范围变化时，同步更新该登记和测试证据。仅分析一个现有功能且未改变路由时，在修改记录中简要写明实际路径即可。

## 9. 验收、效率与切换默认值

本节补充验收项目；测试范围、系统分组、真实应用和全项目回归仍执行 [rules/07](07_测试与发布.md) 与 [rules/12](12_Rust优化与引擎路由.md)，不得因本表只描述一个适配器而缩减既有验收要求。

### 能力验收

同一适配器按“操作 + 格式 + 保留项 + 系统/架构 + 依赖版本范围”记录证据；未执行项写“未执行”。

- 读取对拍：单元格坐标、字段/列序、前导空区、空白/零、文本代码、日期与 1900/1904 日期系统、错误类型和所选公式口径。
- 写入对拍：本次输入输出契约中每个保留项；修改既有文件时同时检查未修改区域和其他 sheet。
- 替换读取引擎前必须声明并统一 bool、日期、错误值的解释口径。基准中 Direct `CellValueProvider` 返回原始缓存值（bool 为 1/0、日期为序列号、错误值为缓存字符串），Calamine 返回解释后的 bool/datetime/error；未统一时不得切换默认读取引擎。依据：基准报告《读取一致性》及附录“type_error_edge_probe”。
- 跨语言读取对拍先归一空单元格记号：本次 `.xls` 侧测中 `python-calamine` 返回 `''`，Rust `calamine` 返回 `Empty`。归一前的摘要不一致不能直接判为数据错误；仍须保持业务空值语义。此观察限定于该侧测文件，其他格式须按各自适配器验收。依据：基准报告附录“real_xls_side_test”。
- 扩展名为 `.xls` 但内容无有效 CFB/OLE 签名的文件，按格式不支持明确拒绝；基准中的 HTML 伪装 `.xls` 属预期拒绝，单独统计，不计为引擎读取失败。依据：基准报告附录“real_xls_side_test”。
- 跨引擎浮点对拍不使用位精确 SHA-256 逐格摘要判等。数值比较使用相对容差不大于 `1e-15`，或按同一十进制规则归一后比较；摘要仅用于同一引擎、同一序列化口径的前后对比。基准实际 S2 输出约 17,580 格中有 23 格相差 1 ULP。若业务契约要求位精确数值，差异未获业务验收前不得切换。依据：基准报告附录“实际 S2 写入：浮点末位（1 ULP）序列化差异”。
- W04 结构修改必须覆盖受影响公式、定义名称、跨表引用、表格/图表引用和打印名称；发现未知依赖时不能登记该对象组合通过。
- 重算使用真实应用修改输入后重复计算并保存，验证传递依赖、错误传播和缓存刷新；mock 不构成公式兼容验收。
- 输出须通过结构检查和目标 reader 重开；涉及应用对象或渲染时使用目标 Excel/WPS/LibreOffice 检查。只用 openpyxl 重开不能证明图表、宏或版面完整。
- 只读输入执行前后 SHA-256 必须相同；授权原地修改的文件先保留输入副本和哈希，最终文件验证预定变更及其余保留项。xlsx 输出比较值和对象语义，不要求整个 ZIP 字节相同。

### 性能与迁移

分别记录读取、业务计算、写入、应用启动/重算/保存和完整流程时间，同时记录峰值内存与输出大小。同机、同输入、同契约预热后至少五次，报告中位数和范围；写入基准使用同一预生成结果，Rust 测量包含桥接成本。ZIP 压缩设置相同的对比和实际交付设置的对比分别记录。

为性能原因切换已有默认值前，先固定真实工作量和现行基线，再确定此次验收口径；用户提供的耗时、内存或规模限制优先采用。用户没有给出数字门槛时，agents 根据该功能的实际工作量预先写明比较条件，不必为常规基准反复询问用户。至少报告端到端和分阶段耗时的中位数、范围、绝对节省时间、相对变化、峰值内存、输出大小、平台与样本规模。只有结果语义无差异、收益稳定且对实际使用有意义时才切换默认；收益很小、仅微基准变快或存在未解决的资源/兼容回退时，保留现有默认并说明测量结果。不得看完结果后再调整验收门槛。

为新增格式/修复兼容问题切换后端时，以原缺陷复现、目标契约通过和受影响回归通过作为切换条件，不要求虚构性能收益。新功能无历史默认时按第 4 节顺序设置首个合格后端。

### 本次基准确认的读取与写入默认值

- XLSX 全表纯值读取默认优先 Calamine 系。基准中 Rust crate 对 50,001×20 全表读取的中位耗时/峰值内存为 1.043 秒/73.7 MB，Direct OOXML 为 12.524 秒/770.1 MB；真实 S2 工作簿 729×16 全表为 0.012 秒/4.0 MB 与 0.210 秒/29.8 MB，纯值坐标/值摘要一致。`python-calamine` 绑定可作为同系列适配器，但须单独通过目标契约验收；报告中的全表计时数据来自 Rust crate。依据：基准报告《读取结果》《读取一致性》（`../../3.open-data-audit-benchmark/results/benchmark_report.md`）。
- 新建工作簿暂不切换现有默认 writer。Rust writer 在多组测试中较快，但耗时优势随规模和 ZIP 压缩设置变化；同类 30 万行×20 列、ZIP level 1 的端到端中位数为 Direct 20.356 秒、Rust 桥接 16.631 秒，峰值内存分别为 376.6 MB 和 1,588.2 MB。实际 S2 热路径同为 ZIP level 6 时，Rust 桥接为 0.050 秒、Direct 为 0.076 秒，但 17,580 格中有 23 格出现 1 ULP 差异。消除桥接层数据复制/JSON 序列化开销、复测内存达标且业务接受浮点口径后，才重评默认值。依据：基准报告《写入结果》、补充复测“实际 S2 写入热路径”及附录“浮点末位（1 ULP）序列化差异”。
- S2 三表结果构造器和 S3 模板原位编辑继续走项目专用 Direct OOXML 路径。`rust_xlsxwriter` 只新建工作簿，不能替代原位编辑或模板部件保留。依据：基准报告《范围与实现审计》《结论》（`../../3.open-data-audit-benchmark/results/benchmark_report.md`）。

## 10. agents 选型输出模板与实例

涉及新后端、用户可选路由、技术方案比较或分系统迁移时，至少输出下表，便于用户确认需求和技术的关系。普通缺陷修复或局部维护不必重复整张表；简要交代受影响的输入输出契约、操作编号、实际后端路径和针对性验证即可，内部仍按本规范检查。

| 字段 | agents 必须给出的内容 |
|---|---|
| 输入 / 输出 | 实际格式、输出形态、公式口径、保留项、允许丢弃项 |
| 操作匹配 | 第 4 节编号，按读取 → 处理 → 写入/转换/渲染顺序列出 |
| 默认方案 | 每个阶段的具体后端及命中的规则；pandas 必须注明底层 engine |
| 用户备选 | 只列同契约且已适配验收的后端；没有备选时写“无” |
| 平台依赖 | 系统/架构、运行时、所需 Office/LibreOffice 组件和原生扩展 |
| 能力缺项 | 未实现、未验收、不支持的项目和对应处理；没有缺项时写“无” |
| 验收证据 | 已运行范围、未运行范围、保留项对拍和实际性能结果 |

实例：

1. **xls/xlsx 时序汇总，新建 xlsx，只要已保存的值。** R01 + W01；默认 Calamine 读取，writer 先用本功能已验收默认；没有既有默认时，按 W01 的 Direct OOXML → rust_xlsxwriter → openpyxl 顺序选首个合格 writer。无需先转换 xls，也不启动 Office。
2. **xlsx 生成可打印 Excel，要边框、合并、行列尺寸和打印区域。** P01；默认 openpyxl。已验收同一保留清单的 Calamine 快路径可供用户选择；未实现该保留清单的快路径不展示。用户另要求 PDF 时增加 P02。
3. **修改 xlsx 中一个数值，保留已有公式和版式。** W02；默认一次 openpyxl 可编辑加载并保存。发现其适配器不覆盖的必需对象时排除该后端；不能通过重新生成整本数据表完成。
4. **批量改 Sheet 名，已有跨表公式和名称。** W04；默认已验收的原生结构编辑适配器；静态适配器只有覆盖全部依赖才可选。禁止仅设置 worksheet.title 后宣称引用已经同步。
5. **含 VBA 的 xls 转 xlsx，同时要求保留宏。** 契约冲突，先让用户确定改为 xlsm，还是明确丢弃宏；不执行转换。改为支持宏的格式后执行 C02 和第 5 节。
6. **Linux 上读取 xlsb 值。** R01，默认 Calamine；要求同时读取合并区域时改为 R05，没有对应已验收原生适配器则报告不支持，不能把缺少合并信息当作未合并。
7. **Windows 的 xls → xlsx 转换，Excel/WPS 两个适配器均已通过该契约。** C02；自动默认 Excel，界面同时提供 WPS。用户手动选 WPS 后只用 WPS，失败时停止；下一次运行保留该选择。输入改为 ET/ETT 时按第 5 节只选择 WPS 原生适配器。

## 11. 技术事实与参考资料

- Calamine 是 reader，python-calamine 的合并信息支持范围、空区行为按锁定版本 API 核对：[项目](https://github.com/dimastbk/python-calamine)、[API 声明](https://github.com/dimastbk/python-calamine/blob/master/python/python_calamine/_python_calamine.pyi)。库版本升级不能自动扩大项目验收范围。
- Rust crate 与 Python 包装层要区分：`rust_xlsxwriter` 和 `umya-spreadsheet` 的上游项目是 Rust 库，不能直接当作 Python 模块导入；Python 项目可通过 PyO3/maturin 等绑定、稳定的 C ABI/CLI，或第三方 Python 包调用 Rust 实现。Python 包 `XlsxWriter` 是独立的 Python 实现，不是 `rust_xlsxwriter` 的 Python 绑定。第三方包装层须单独核对 Python ABI、Windows/Linux wheel、glibc、Win7 支持、输出能力和本项目的保留项；不可因其底层使用 Rust 就直接登记为已验收后端。[rust_xlsxwriter](https://github.com/jmcnamara/rust_xlsxwriter)、[umya-spreadsheet](https://github.com/MathNya/umya-spreadsheet)、[Python XlsxWriter](https://pypi.org/project/XlsxWriter/)。
- pandas 读取依赖指定的 Excel engine；xlrd 2.x 只读 xls：[pandas IO](https://pandas.pydata.org/docs/user_guide/io.html#excel-files)、[xlrd](https://xlrd.readthedocs.io/en/latest/)。
- openpyxl 不计算公式；单工作簿 copy_worksheet 不提供跨工作簿完整复制：[教程](https://openpyxl.readthedocs.io/en/stable/tutorial.html)、[公式](https://openpyxl.readthedocs.io/en/stable/simple_formulae.html)、[结构修改依赖](https://openpyxl.readthedocs.io/en/stable/editing_worksheets.html)、[批注](https://openpyxl.readthedocs.io/en/stable/comments.html)。
- Direct OOXML 是 ZIP/XML 访问方式，不是具体库。写入适配器必须使用 namespace-aware XML parser，维护关系、Content Types、sheet 身份/顺序、共享字符串和名称引用；不以正则替换 XML 全文实现通用结构修改。
- rust_xlsxwriter 创建新工作簿，不读取或编辑已有文件；umya-spreadsheet 必须有本项目桥接适配器和对应对象验收才进入候选：[rust_xlsxwriter](https://docs.rs/rust_xlsxwriter/latest/rust_xlsxwriter/workbook/struct.Workbook.html)、[umya](https://github.com/mathnya/umya-spreadsheet)。
- LibreOffice 与 Excel 的转换、公式和对象语义存在差异；该事实落实为具体契约验收和能力排除，不能写成“默认等价”：[LibreOffice 兼容说明](https://help.libreoffice.org/latest/en-US/text/shared/guide/ms_import_export_limitations.html)。
- ET/ETT 与标准 Excel 文件分别处理：[WPS ET](https://www.wps.com/feature/et-file/)、[WPS ETT](https://www.wps.com/blog/how-to-open-convert-and-create-ett-file/)。
- 宏格式与 COM 位数边界：[Microsoft 文件格式](https://learn.microsoft.com/en-us/office/compatibility/office-file-format-reference)、[Microsoft 进程互操作](https://learn.microsoft.com/en-us/windows/win32/winprog64/process-interoperability)。
- 项目约束入口：[AGENTS.md](../AGENTS.md)；文件硬边界：[rules/03](03_Excel与OOXML边界.md)；测试与迁移：[rules/07](07_测试与发布.md)、[rules/12](12_Rust优化与引擎路由.md)；修改记录：[rules/08](08_AI协作与修改记录.md)；版本：[rules/11](11_版本管理与组件编号.md)。
